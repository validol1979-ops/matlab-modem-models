# RTL-реализации DSP-алгоритмов

Навигация по законченным DSP-блокам проекта и их целочисленным эталонам. Исполняемых `.sv` в этом подкаталоге нет: реализации находятся в общей RTL-библиотеке.

## Что это

Каталог зарезервирован для отдельных верхних уровней алгоритмов. Текущие реализации FFT/STFT/PFB, FIR/IIR, адаптивных фильтров, декодеров, матричных решателей и OM-LSA размещены в [../common](../common/README.md). У них есть битоточные Python-модели и HDL-проверки; прежняя пометка об отсутствии полных DSP-моделей устарела.

Переносимые алгоритмические аналоги исторических MATLAB-примеров находятся в [algorithms](../../algorithms/), общая Python/Octave/поведенческая SV-реализация — в [common](../../common/). Наличие численного RTL-теста не означает завершённого физического синтеза: статус каждого блока следует проверять по профильному документу.

## Как работает

Для отдельного алгоритма цепочка имеет вид: конфигурация → поток входных слов → DSP-ядро → поток результатов. Например, OM-LSA объединяет отражённое дополнение → STFT → оценку спектрального усиления → ISTFT → вырезку исходного интервала. MMSE сначала вычисляет веса `W=(HᴴH+λI)⁻¹Hᴴ`, затем применяет их к потоку наблюдений. LMS/RLS дополнительно выдают итоговые веса на независимом порту `w_*`.

| Семейство | Параметры/контракт | Описание |
| --- | --- | --- |
| FFT, OFDM, STFT, PFB | FFT N=4…1024; STFT N=4…256, `N/HOP` = 1/2/4; PFB M=4…64 | [FFT_RTL.md](../../docs/FFT_RTL.md) |
| FIR, notch, Kalman, FSK, beamforming, Alamouti, LMS/RLS, LDPC | Коэффициенты/матрицы через `cfg_*`; границы по `s_last` | [DSP_RTL.md](../../docs/DSP_RTL.md) |
| MMSE 3×3 | Точный целочисленный расчёт Gram/adj/det и веса Q24 | [RTL_MMSE3.md](../../docs/RTL_MMSE3.md) |
| MMSE N×N | N=2…8, нормализация и исключение Гаусса | [RTL_MMSE_N.md](../../docs/RTL_MMSE_N.md) |
| OM-LSA | `(N,HOP)` = (16,4), (32,8), (64,16), 1…16 начальных кадров шума | [DSP_RTL.md](../../docs/DSP_RTL.md) |

Большинство временных входов — signed 18/15, спектры STFT/PFB — signed 24/19. Интерфейс valid/ready следует правилам AXI-Stream, но порты плоские и специфичны для алгоритма. Задержка и производительность различаются: FFT принимает плотный поток по отсчёту за такт, LMS обновляет веса последовательно, RLS/MMSE используют последовательное деление. Полная таблица модулей и параметров — в [общей библиотеке](../common/README.md).

## Как запустить

Из корня проекта. Нужны Python с зависимостями [requirements-rtl.txt](../../requirements-rtl.txt); для `lint` — Verilator, для `hdl/all` — Questa/UVM 1.2.

```bash
python3 tools/run_streaming_rtl.py --suite python
python3 tools/run_streaming_rtl.py --suite lint --blocks fft fir lms mmse_n
python3 tools/run_streaming_rtl.py --suite all
python3 tools/run_dsp_uvm.py --suite all
```

Первая команда проверяет целочисленные модели всех 17 потоковых наборов; вторая ограничивает lint выбранными семействами. Третья добавляет численные HDL-проверки и тесты мониторов. Четвёртая запускает отдельную полную UVM-матрицу DSP на внешних контактах. Объединённый потоковый runner включает также OQPSK, поэтому его набор шире чистых DSP-алгоритмов. Синтез этими командами не выполняется.

## Что смотреть

Сводка — `build/rtl/streaming/<suite>_results.json`, подробности — `build/rtl/<block>/<suite>_results.json`; UVM — `build/rtl/dsp_uvm/`. Проверяйте завершение PASS, хеши исходников/артефактов и успешное обнаружение намеренных ошибок. Для фильтров полезны prediction/error, итоговые веса и число насыщений; для решателей — веса, ошибка относительно вещественного решения и отказы вырожденных конфигураций; для спектральных блоков — масштаб, порядок бинов и ошибка восстановления.

Документы по точности: [RTL_LINEAR_PRECISION.md](../../docs/RTL_LINEAR_PRECISION.md), [RTL_ADAPTIVE_PRECISION.md](../../docs/RTL_ADAPTIVE_PRECISION.md), [RTL_SPECTRAL_PRECISION.md](../../docs/RTL_SPECTRAL_PRECISION.md). [Типизированный визуальный отчёт](../../docs/typed_visual/index.html) показывает переносимые модели; [RTL_DSP_UVM.md](../../docs/RTL_DSP_UVM.md) описывает именно RTL-проверку.

## Ограничения

Это навигационный каталог, отдельной команды его сборки нет. Параметры, точность и ограничения памяти задаются конкретным модулем; поддержка диапазона параметров не означает проверки каждой комбинации. MMSE N×N битоточен своей модели, но использует округления и не является точным вещественным решателем. Синтез и Fmax новых конфигураций не подтверждаются результатами симуляции.

Исторические сторонние материалы не входят в публичную версию; их метаданные сохраняются в `model.json` соответствующих переносимых моделей. Проверки оригинальных MATLAB-скриптов, в отличие от независимых RTL-эталонов, доступны только при наличии исходных материалов.
