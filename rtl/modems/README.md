# Потоковые RTL-модемы

Передатчики и приёмники с фиксированной точкой, кадровыми границами и рукопожатием valid/ready. Общий PSK/QAM-тракт развивает BPSK-пилот; CPM, OQPSK, OFDM и SIMO используют его арифметику или блоки общей библиотеки.

## Что это

Здесь находятся синтезируемые SystemVerilog-реализации. Их целочисленные эталоны — в [common/python](../../common/python/), переносимые Python/Octave/MATLAB и поведенческие SV/UVM-модели — в [modems](../../modems/). Это разные уровни реализации: успешная проверка вещественной модели сама по себе не подтверждает fixed-point RTL.

BPSK, MSK/GMSK, OQPSK, SIMO и OFDM имеют численные тестбенчи; для передатчиков и пакетных приёмников есть полноценные UVM-окружения. Исторические результаты физической приёмки описаны в документах каждого семейства. Изменённые после этих результатов захват PSK/QAM и петля OQPSK требуют нового подтверждения тайминга.

## Как работает

Типовая цепочка — метки символов → mapper/дифференциальный кодер → формирование импульсов → комплексные отсчёты → внешний канал → согласованный фильтр/оценка синхронизации → решение и декодирование. Канал, шум и искажения для проверок создаются вне DUT.

| Семейство | Ключевые параметры и обработка |
| --- | --- |
| BPSK и общее PSK/QAM-ядро | `ORDER=2/4/8/16/64`, 8 отсчётов/символ, RRC 33 отвода; 192 обучающие метки, RX 192…2048 символов |
| MSK/GMSK | `GMSK=0/1`, 8 отсчётов/бит; непрерывная фаза, у GMSK Gaussian BT=0.3; дискриминатор MSK и когерентный RX GMSK |
| OQPSK | 8 отсчётов/символ; Q задержана на 4 отсчёта, раздельные I/Q-моменты решения |
| SIMO | Две синхронные ветви; MRC с известными усилениями/дисперсиями перед профилем `QPSK_DIFF` |
| OFDM | `N=2^LOG2N`, `LOG2N=2…10`, `CP=0…N`; IFFT/FFT и вставка/удаление CP |

I/Q обычно имеют формат signed 18/15. Передача — на фронте при `valid && ready`, данные и `last` удерживаются во время остановки. TX и RX считают границы по разным единицам: меткам символов и отсчётам формы сигнала соответственно. Фазовые состояния используют 32-битный циклический код. Точные интерфейсы, правила округления и задержки даны в README ниже и [общем контракте](../../docs/RTL_CONTRACT.md).

## Как запустить

Из корня проекта; Python с NumPy/PyYAML по [requirements-rtl.txt](../../requirements-rtl.txt), Verilator для lint, Questa/UVM 1.2 для HDL:

```bash
python3 tools/run_bpsk.py --suite all
python3 tools/run_cpm.py --suite all
python3 tools/run_oqpsk.py --suite all
python3 tools/run_ofdm.py --suite all
```

Каждая команда объединяет Python-тесты, lint и численную HDL-проверку семейства. `run_bpsk.py` охватывает также профили PSK/QAM и SIMO; `run_cpm.py` — MSK и GMSK. Для запуска без HDL-инструментов заменить `all` на `python`, для одного lint — на `lint`.

Полноценные UVM-наборы запускаются отдельно:

```bash
python3 tools/run_bpsk_uvm.py --suite all --pilot both --profile all
python3 tools/run_psk_tx_uvm.py --suite all
python3 tools/run_packet_rx_uvm.py --suite all
python3 tools/run_cpm_uvm.py --suite all
python3 tools/run_oqpsk_uvm.py --suite all
python3 tools/run_dsp_uvm.py --suite all --case ofdm_tx_n32_cp8
```

Последняя команда проверяет один OFDM TX case; полная матрица DSP запускается с `--case all`. Описание сценариев — в [tb/README.md](../tb/README.md). Octave/MATLAB для fixed-point RTL-прогонов не требуются; они нужны для отдельной сверки переносимых моделей или оригинала.

## Что смотреть

Основные результаты — `build/rtl/bpsk/`, `cpm/`, `oqpsk/`, `ofdm/`; UVM — `build/rtl/bpsk_uvm/`, `psk_tx_uvm/`, `packet_rx_uvm/`, `cpm_uvm/`, `oqpsk_uvm/`, `dsp_uvm/`. В полном прогоне ищите `all_results.json`, журналы сценариев и векторы. PASS должен быть завершённым и соответствовать текущим хешам исходников.

Численные проверки сравнивают выходы и оценки захвата бит в бит. SER считается по полезным символам после 192 обучающих меток; для минимального кадра из 192 символов полезная нагрузка пуста и SER не определена. В UVM пакетных RX есть независимая вещественная оценка SER на тех же квантованных входах: [RTL_BPSK_UVM.md](../../docs/RTL_BPSK_UVM.md), [RTL_PACKET_RX_UVM.md](../../docs/RTL_PACKET_RX_UVM.md). Геометрия, темп и задержки на контактах — в [RTL_MODEM_PIN_RATES.md](../../docs/RTL_MODEM_PIN_RATES.md). Визуальные отчёты: [основной](../../docs/visual/index.html), [типизированный](../../docs/typed_visual/index.html).

## Ограничения

Захват по известной преамбуле не воспроизводит исторические слепые петли и расписание Simulink. OFDM получает уже сформированные комплексные символы и не содержит синхронизатора пакетов или карты исторических пилотов. SIMO требует известных усилений и общей задержки ветвей. Для всех блоков обратное давление может снижать темп; симуляционные такты не являются измерением Fmax.

Исторические исходники в публичную версию не входят. Ссылки на извлечённые параметры и доступные метаданные, а также условия MATLAB-проверок приведены в README отдельных модемов. Эти исходники не нужны обычным fixed-point эталонам, но нужны для повторной проверки оригиналов и получения MATLAB-захватов.
