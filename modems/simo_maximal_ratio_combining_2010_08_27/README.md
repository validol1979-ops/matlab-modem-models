# SIMO QPSK-модем с объединением по максимальному отношению (2010-08-27)

Кадровая модель QPSK с двумя приёмными ветвями и их взвешенным объединением до демодуляции.

## Что это

Исторический прототип — Simulink-модель `simo_maximal_ratio_combining_2010_08_27.mdl`. Переносимые реализации есть на Python, Octave/MATLAB и поведенческом SystemVerilog с UVM. Отдельно существует потоковый fixed-point RTL. Общие Python-тесты проверяют кодер, передачу без шума, канал с шумом/задержкой/несущей, повторяемость, неверный ввод и отрицательный контроль при −8 дБ; специальные проверки зависят от конфигурации. Сохранённые результаты межъязыковых прогонов описаны в [VERIFICATION.md](../../docs/VERIFICATION.md). Совпадение переносимых реализаций не устанавливает полную эквивалентность историческому приёмнику.

Историческая модель в публичный репозиторий не входит. В [source_parameters.json](source_parameters.json) сохранены извлечённые поля блоков и номера строк `source_line`; происхождение и SHA-256 исходного файла записаны в полях `source` и `source_sha256` файла [config.json](config.json). Размер исходника — 238466 байт по [архивному манифесту](../../docs/archive_inventory.json), который также содержит его SHA-256. В `source_parameters.json` записаны параметры блоков, а не полный манифест файла; `model.json` в этом модуле отсутствует.

## Как работает

1. TX получает целочисленные метки, выполняет заданное конфигурацией кодирование и выбирает комплексные точки из таблицы `constellation`.
2. После вставки нулей импульсы проходят через RRC-фильтр единичной энергии: 33 коэффициента, порядок 32, `rolloff=1`. Возвращается сигнал вместе с хвостом FIR.
3. `channel` моделирует AWGN, усиление, поворот фазы, частотное смещение и дробную задержку; для специальных проверок доступны эхо и дрейф тактов.
4. RX применяет согласованный RRC и ищет задержку от 0 до 16 отсчётов с шагом 0.25. Четырёхточечная кубическая интерполяция Лагранжа задаёт дробные моменты выборки. Наклон развёрнутой фазы на преамбуле оценивает частоту, комплексная корреляция — фазу и усиление.
5. При `timing=gardner` момент выборки корректируется по ошибке `Re((late−early)·conj(mid))`. Затем работают петля несущей второго порядка, АРУ, выбранный эквалайзер и решение по минимуму `|y−c|²`; после решения выполняется декодирование меток.

Перед согласованным фильтром ветви объединяются по формуле `y=Σ(conj(gᵢ)·xᵢ/σᵢ²)/Σ(|gᵢ|²/σᵢ²)`. В [modem_core.py](../../common/python/modem_core.py) это отдельная функция `maximal_ratio_combine(branches, gains, variances=None)`, по умолчанию дисперсии равны единице. Сам `receive` принимает уже объединённый одномерный сигнал; оценка усилений ветвей в объединитель не входит. Дифференциальный кодер QPSK накапливает код Грея метки по модулю 4.

`receive(CONFIG, waveform, preamble, count)` получает только известную преамбулу и длину кадра; полезные метки ему не передаются. Минимум преамбулы — 32 символа, в демонстрациях используется 192 из 768 (полезная часть 576). Начало кадра грубо известно вызывающей стороне; это не детектор произвольных пакетов.

| Параметр | Значение |
| --- | --- |
| `family` / `order` | `psk` / 4 |
| Входные метки | 0…3; 2 бита на метку |
| `differential` | `psk` |
| `sps` | 8 |
| RRC | `rrc_order=32`, 33 коэффициента, `rolloff=1.0` |
| `timing` / `carrier` | `gardner` / `feedback` |
| `equalizer` | `none` |
| `diversity_branches` | 2 |
| `variable_delay` / `phase_noise` | `false` / `false` |

RTL [simo_rx](../../rtl/modems/simo_maximal_ratio_combining_2010_08_27/simo_rx.sv) содержит двухветвевой [fxp_mrc2](../../rtl/common/fxp_mrc2.sv) перед `bpsk_rx` с `ORDER=4`, `DIFFERENTIAL=1`. TX — `bpsk_tx` с теми же параметрами. Эталоны — [mrc_fixed.py](../../common/python/mrc_fixed.py) и профиль `QPSK_DIFF` в [psk_fixed.py](../../common/python/psk_fixed.py).

Два комплексных отсчёта подаются совместно через `s_a_re/s_a_im/s_b_re/s_b_im`, на одном такте и с общей задержкой. Усиления `gain_a/b` и отсчёты имеют Q3.15, дисперсии `variance_a/b` — целые 1…65535 в общем масштабе, веса — 18-битные Q4.14 с модулем меньше 8. После `gain_valid` веса рассчитываются один раз последовательным делителем примерно за 310 тактов; нулевая дисперсия, нулевой знаменатель или непредставимый вес дают `gain_error`. [Форматы и ограничения MRC](../../docs/BPSK_RTL.md#simo-mrc).

Потоковый тракт использует рукопожатие `s_valid/s_ready` и `m_valid/m_ready`, входные ветви `s_a_re/s_a_im/s_b_re/s_b_im` и комплексный выход `m_re/m_im` и признаки `s_last/m_last`. Перед RX загружаются 192 метки через `cfg_valid/cfg_ready/cfg_bit/cfg_last`; `cfg_count` задаёт длину 192…2048 символов. Передача происходит только при `valid && ready`, остановка выхода удерживает данные. Комплексные отсчёты — знаковые 18 бит с 15 дробными (Q3.15, −4…4−2⁻¹⁵), фаза и частота — 32 бита, полный оборот равен 2³². Округление — к ближайшему чётному, с насыщением в соответствующих узлах.

RX принимает `8N…8N+64` входных отсчётов с признаком конца кадра, затем дополняет согласованный FIR 32 нулями; в это время вход остановлен.

Латентности общих RRC, интерполятора и ротатора — 8, 7 и 7 разрешённых тактов; каждый имеет II=1. Полная задержка RX зависит от накопления кадра, захвата и остановок. RTL использует early-late-сопровождение времени; переносимая модель использует Gardner. Форматы, правила сброса, ограничения кадров и результаты прежних проверок приведены в [описании RTL](../../docs/BPSK_RTL.md).

### Историческая схема

Модель Simulink демонстрирует приём одного QPSK-сигнала по двум ветвям и их адаптивное объединение. Передатчик: скремблер → код Грея и дифференциальное кодирование → QPSK → повышение частоты → RRC. Канал: общая переменная задержка `channel_delay`, двухветвевой `simo_flat_fading_channel` с усилениями, задержками и фазовыми/частотными смещениями, AWGN. Приёмник: RRC → коррекция фазы и усиления → кубический Фарроу → адаптивный LMS-фильтр/объединитель в `2_sps_clock_domain` → решения и декодирование.

Есть детектор Гарднера, фазовый детектор по решениям, слепой детектор Годара, обновление коэффициентов и петлевые фильтры. Объединитель реализован адаптивным фильтром; результаты для идеального MRC с заранее известными каналами здесь не заявляются.

Параметры: две приёмные ветви; 4 отсчёта на символ в передающем тракте, промежуточная обработка при 2 отсчётах на символ. Таблица передатчика: `exp(i*([0:3]*pi/2+pi/4))`, четыре единичные точки QPSK. Это параметры исходной Simulink-модели.

### Собственная реализация (run_own)

Автономная реализация на MATLAB/Octave и Python читает существующий [config.json](config.json) и работает без тулбоксов и исторических файлов, в том числе в публичной копии. Общий код — [common/own/](../../common/own/) и [common/own/python/](../../common/own/python/). Передатчик, канал и приёмник написаны кодом; параметры переносимого профиля могут отличаться от исторической схемы.

| Узел | Реализация |
| --- | --- |
| Модуляция | PSK, 4 позиций |
| Отсчётов на символ | 8 |
| Формирующий фильтр | корень из приподнятого косинуса, порядок 32, скругление 1 |
| Кодирование | дифференциальное фазовое |
| Символьная синхронизация | петля Гарднера с кубическим интерполятором Фарроу |
| Фазовая синхронизация | ФАПЧ второго порядка (фаза и частота), плюс АРУ |
| Эквалайзер | нет |
| Разнесённый приём | 2 ветви, объединение с максимальным отношением (MRC) |

Модель канала: ослабление 0,65, фазовый сдвиг 0,38 рад, сдвиг частоты 1,5·10⁻⁴ от частоты дискретизации, дробная задержка 2,25 отсчёта и белый шум. Сценарий для этого модема: **две ветви приёма с разным замиранием, MRC**. Первые 192 символа кадра служат известной преамбулой. По ней оцениваются задержка, частота и начальная фаза, обучается эквалайзер, если он предусмотрен конфигурацией. Дальше приёмник работает в режиме решений.

## Как запустить

Все команды выполняются из корня проекта. Для переносимого Python нужны Python 3 и NumPy; для M-файлов — `octave-cli` с `jsondecode` либо MATLAB. Симуляция поведенческого SV требует Questa и UVM 1.2. Полный RTL-прогон дополнительно использует Verilator для lint; пути Questa/UVM выбираются общими средствами проекта.

Демонстрация печатает JSON с числом ошибок и оценками синхронизации; тест запускает семь проверок общего контракта:

```bash
python3 modems/simo_maximal_ratio_combining_2010_08_27/python/modem.py
python3 modems/simo_maximal_ratio_combining_2010_08_27/tests/test_modem.py
```

Проверка M-реализации и её демонстрация:

```bash
octave-cli --quiet --eval "addpath('modems/simo_maximal_ratio_combining_2010_08_27/octave'); test_modem; run_modem;"
```

Сравнение Python и Octave на общих векторах, затем отдельный поведенческий UVM-прогон:

```bash
python3 tools/run_tests.py --suite cross --modem simo_maximal_ratio_combining_2010_08_27
./tools/run_questa.sh --modem simo_maximal_ratio_combining_2010_08_27
```

Общая проверка fixed-point-моделей, lint и RTL-симуляции (охватывает всю группу, а не только этот каталог):

```bash
python3 tools/run_bpsk.py --suite all
```

Проверка исторического прототипа доступна только при наличии его исходников и требуемых библиотек MATLAB/Simulink. Она запускает симуляцию и повторный расчёт для проверки точной повторяемости:

```bash
./tools/matlab.sh -nodisplay -batch "addpath('modems/simo_maximal_ratio_combining_2010_08_27/matlab'); test_original;"
```

Логи и захваты исторической проверки сохраняются в `build/matlab_originals/compatible/simo_maximal_ratio_combining_2010_08_27/`, в том числе `signals.mat`. Для сохранённых результатов использовался MATLAB R2020b. Сведения об адаптациях следует читать отдельно от статуса исходной схемы; `test_original` не проверяет BER всего исторического приёмника. Условия описаны в [MATLAB_MODEM_VERIFICATION.md](../../docs/MATLAB_MODEM_VERIFICATION.md).

### Быстрый старт в MATLAB

Перейдите в папку этого модема. [run_demo.m](run_demo.m) открывает подготовленную R2020b-копию `matlab/simo_maximal_ratio_combining_2010_08_27.mdl`:

```matlab
run_demo          % историческая схема и её осциллографы
run_demo(32768)  % явное время окончания
```

По умолчанию время окончания — `32768` в единицах модельного времени, не число символов. Нужны MATLAB R2020b, Simulink, Communications Toolbox и DSP System Toolbox (с их зависимостью Signal Processing Toolbox). Историческая модель не входит в публичный репозиторий, см. [THIRD_PARTY.md](../../THIRD_PARTY.md); без локальной копии `run_demo` выдаёт понятную ошибку. Автономный `run_own` работает и без неё.

MATLAB или GNU Octave (один и тот же код):

```matlab
run_own                              % демонстрация с графиками
run_own(struct('snr_db', 12))        % свой SNR на отсчёт, дБ
r = run_own(struct('plot', false))   % только числа, без графиков
```

Python (зависимости: [requirements.txt](../../requirements.txt) и, для графиков, [requirements-visual.txt](../../requirements-visual.txt)):

```bash
python3 run_own.py                    # демонстрация с графиками
python3 run_own.py --snr 12           # свой SNR на отсчёт, дБ
python3 run_own.py --no-plot --json   # только числа
```

Можно сохранить графики без окна: `python3 run_own.py --no-plot --save images/generated`. Для короткой проверки кривой задайте `--sweep -10 10 24`; без этой опции сохраняется исходная сетка SNR.

## Что смотреть

В демонстрации `symbol_errors` — число неверных меток после преамбулы, `ser` — их доля в 576 полезных символах. Для штатного примера ожидается ноль ошибок. `estimated_delay` измеряется в отсчётах, `estimated_frequency` — в циклах на отсчёт. SNR задаётся на отсчёт по средней мощности сигнала и не равен Eb/N0. Нулевой SER на коротком кадре не определяет долговременную BER.

Python-тесты заканчиваются `OK`, Octave печатает `PASS <имя> Octave codec and waveform loopback`. В проверенном окружении Octave при завершении также печатает `ignoring const execution_exception`; учитывайте код выхода и результат утверждений теста. Проверка канала при 30 дБ использует усиления 0.65/0.2, фазы 0.38/−1.1 рад, частоты 0.00015/−0.0005 циклов на отсчёт и задержки 2.25/7.25; требуется точное восстановление нагрузки, ошибка частоты менее 10⁻⁵ и задержки не более 0.5 отсчёта. Отрицательный контроль при −8 дБ должен дать больше 20 ошибок.

`run_tests.py --suite cross` сохраняет `build/single/simo_maximal_ratio_combining_2010_08_27/cross_results.json`, лог `logs/cross/octave.log` внутри этого каталога и общие векторы `build/vectors/simo_maximal_ratio_combining_2010_08_27/`. Поведенческий UVM пишет `build/questa/single/simo_maximal_ratio_combining_2010_08_27/results.json` и `simo_maximal_ratio_combining_2010_08_27.log` в том же каталоге. Успех требует четырёх проверенных кадров, `UVM_ERROR : 0`, `UVM_FATAL : 0` и обнаружения специально внесённого несовпадения в отрицательном контроле.

UVM передаёт чистый, шумовой и специальный сценарии, затем повторяет первый кадр после сброса. Пассивный монитор снимает реальные выходы; scoreboard сверяет TX-отсчёты, RX-символы, индексы, декодированные и полезные метки и оценки синхронизации с независимым исполнением Python. Комплексные величины сравниваются с допуском 10⁻⁷, целочисленные метки — точно. Поведенческое завершение за один цикл запроса является абстракцией кадра, не аппаратной латентностью. Комментарии общей реализации — на русском, диагностика — преимущественно на английском.

Fixed-point-прогон сохраняет `build/rtl/bpsk/all_results.json` и логи подкаталогов. Его побитное совпадение с целочисленным эталоном проверяет RTL-арифметику; качество относительно вещественного приёмника оценивается отдельно в указанной RTL-документации.

Специальный тест MRC использует усиления `0.2+0.3j` и `1−0.4j`, проверяет уменьшение средней квадратичной ошибки относительно первой ветви после компенсации её усиления и отсутствие ошибок после демодуляции объединённого сигнала. Обычная демонстрация `run_demo` проверяет один уже подготовленный сигнал; две ветви создаёт именно специальный тест.

Сохранённые исторические захваты и три переносимых сценария доступны в [интерактивном отчёте](../../docs/visual/index.html#section=explorer&model=simo_maximal_ratio_combining_2010_08_27), [MATLAB-графике](../../docs/visual/matlab/simo_maximal_ratio_combining_2010_08_27.png) и [полном PDF](../../docs/visual/modem_test_report.pdf). Единицы и смысл панелей описаны в [VISUAL_TESTS.md](../../docs/VISUAL_TESTS.md). В визуальном отчёте по 320 полезных символов; BER считает различающиеся биты двоичных меток, SER — ошибочные метки, преамбула исключена.

![Переносимая модель: канал с искажениями](../../docs/visual/portable/simo_maximal_ratio_combining_2010_08_27/case_1.png)

Смотрите форму I/Q, восстановленные точки, спектр и ошибки символов. Облако исторического RX может содержать удерживаемые или передискретизированные отсчёты и само по себе не измеряет BER. Сохранённые изображения и JSON относятся к зафиксированным запускам.

В [verification.json](matlab/verification.json) записаны `runtime_status=PASS`, `repeat_status=PASS`, но `receiver_functional_status=NOT_ESTABLISHED` и `full_equivalence=NOT_ESTABLISHED`. Для симуляции явно заданы размерности входов интерполятора Farrow: 2 для каналов и 1 для временной позиции; проверка маппера дала расхождение 0. Сведения о миграции и проверках не означают эквивалентности исторической версии MATLAB.

### Осциллографы исторической схемы

- Автоматически открывается `Discrete-Time Scatter Plot Scope`: символы после объединения; смотрите четыре группы QPSK и остаточный разброс.
- `Filter Taps` и `Filter Taps1` открываются автоматически: действительная и мнимая части адаптивных коэффициентов. `Spectrum Scope` — спектр после AWGN.
- Вручную откройте `Scope`: три выхода тактового NCO; `Scope1` — I/Q сигнала после AWGN; `Scope3` — декодированные метки. Отдельного сравнения BER одной и двух ветвей модель не выводит.

## Ограничения

Полная эквивалентность историческому прототипу не установлена. Переносимая модель заменяет слепой захват обучением по преамбуле и не воспроизводит скремблеры/дескремблеры, внутренние CIC, исходные коэффициенты петель, переходные процессы, точное многоскоростное расписание и округление старых блоков. Некоторые исторические варианты поэтому используют общий текущий алгоритм. [Контракт переноса](../../docs/PORTING_CONTRACT.md) описывает эти замены и проверенные сценарии.

`sv/modem.sv` использует `real` и кадровые транзакции; синтезируемый fixed-point RTL находится отдельно. Статусы из сохранённых отчётов относятся к их снимкам исходников; физический тайминг старого снимка не переносится автоматически на текущий RTL. Работа на реальной плате не подтверждена этими моделями. Тесты каналов являются регрессионными примерами, а не измерением полного диапазона захвата или гарантией BER.

MRC требует известных комплексных усилений, положительных дисперсий и согласованных временных шкал ветвей. Оценка канала и выравнивание разных задержек отсутствуют; для RTL веса должны помещаться в Q4.14.

### Автономная демонстрация

`run_own` использует известную преамбулу; исторические скремблеры, точные коэффициенты петель и фиксированная точка не воспроизводятся. Версии MATLAB/Octave и Python проверяются на одном входном сигнале через `own_cross_check` (см. [корневой README](../../README.md#быстрый-старт-в-matlab)). Сохранённые картинки построены в MATLAB; Python генерирует шум иначе, поэтому отдельные значения SER могут отличаться. Сохранённые результаты относятся к автономной реализации, а не к исторической схеме.
