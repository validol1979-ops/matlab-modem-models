# DSP-SOS: переносимый каскад biquad

`rtl/common/sos_iir.sv` реализует transposed direct form II (DF2T), 1/2/4
последовательные SOS-секции, независимо для I и Q. Эталон — неизменённый
`common/python/ext_signal_sos.py::SOSFilterFixed`. Тонкая обвязка
`common/python/sos_rtl_cases.py` наблюдает вызовы насыщения существующей модели
и записывает векторы; арифметику модели она не заменяет.

## Интерфейс и числовые форматы

Передача любого канала происходит на фронте `clk` при `valid && ready`.

| Канал/сигнал | Назначение |
| --- | --- |
| `s_valid/s_ready/s_last`, `s_re/s_im` | Вход, две signed18 компоненты, полный диапазон −131072…131071 |
| `m_valid/m_ready/m_last`, `m_re/m_im` | Выход, две signed18 компоненты, симметричный диапазон −131071…131071 |
| `cfg_valid/cfg_ready/cfg_last` | Отдельный канал коэффициентов; одно слово содержит одну секцию |
| `cfg_b0/b1/b2/a1/a2` | Пять signed32 целочисленных кодов с `COEF_FRAC` дробными разрядами |
| `configured` | Полная допустимая конфигурация загружена |
| `error` | Залипающая ошибка конфигурации; снимается только сбросом |
| `saturated` | Залипающее насыщение выхода любой секции или любого состояния, обоих каналов |
| `clk/rst` | Единственный домен; синхронный сброс с полярностью `RESET_ACTIVE` |

Параметры: `COEF_FRAC=28` (16…28), `STATE_BITS=64` (40…64),
`RESET_ACTIVE=1` (0 или 1). Входной и выходной масштабы одинаковы; для
модемного тракта их можно трактовать как Q15. Состояния хранят числитель
рекурсии, то есть имеют `15+COEF_FRAC` дробных разрядов при входе Q15.

Нормировка `a0=1`, распределение усиления между секциями и квантование
выполняются на стороне Python. Передавать следует именно `model.sos` после
`SOSFilterFixed.configure`, исключая колонку `a0`. RTL не выполняет повторное
балансирование, не вводит дополнительных масштабов и не меняет порядок секций.
Ширина хранения коэффициента всегда 32 бита; `COEF_FRAC` задаёт только масштаб.

Для одного канала и одной секции:

```text
Y  = floor((b0*X + S1 + 2^(F−1)) / 2^F)
y  = clamp(Y, −131071, 131071)
S1 = clamp(b1*X − a1*y + old_S2, −(2^(B−1)−1), 2^(B−1)−1)
S2 = clamp(b2*X − a2*y,          −(2^(B−1)−1), 2^(B−1)−1)
```

Здесь F=`COEF_FRAC`, B=`STATE_BITS`; `y` становится входом следующей секции.
Округление половины направлено к +∞, в том числе для отрицательных значений:
при коэффициенте 0.5 коды −1,+1,−3,+3 переходят в 0,+1,−1,+2.
Состояния насыщаются после полного вычисления, без усечения произведений.

## Конфигурация, TLAST и ошибки

Конфигурация принимается только между кадрами при пустом тракте, включая
непрочитанный выход. `cfg_last` ставится на 1-й, 2-й или 4-й секции. С первой
принятой строки `configured=0`; во время частичной конфигурации данные не
принимаются. Паузы канала конфигурации разрешены. Успешное окончание
конфигурации очищает все состояния и `saturated`.

Если `cfg_valid && cfg_ready`, `s_ready=0` независимо от `s_valid`.
Ожидающая конфигурация внутри открытого кадра не останавливает оставшиеся
входные отсчёты. Кадр остаётся открытым до **потребления** выходного слова
с `m_last=1`, включая паузы источника и остановку последнего выхода.

`s_last` является тегом окончания кадра и проходит с соответствующим выходом;
никакого дополнения нулями или выдачи хвоста нет. Число выходов равно числу
принятых входов. Состояния **сохраняются через TLAST**, как при последовательных
вызовах `SOSFilterFixed.push`. Кадр может состоять из одного слова или иметь
произвольную длину. До TLAST новая конфигурация ждёт, даже если между
отсчётами тракт временно пуст. Отсутствие TLAST не вызывает числовой ошибки,
но не позволяет сменить конфигурацию.

Для квантованных `a1,a2` проверяются точные строгие условия Jury/Schur:

```text
−2^F < a2 < 2^F
 2^F + a1 + a2 > 0
 2^F − a1 + a2 > 0
```

Это необходимые и достаточные условия расположения корней вещественного
`z²+(a1/2^F)z+a2/2^F` строго внутри единичной окружности. Корни на окружности
отвергаются. Проверка действует на каждую строку до записи коэффициентов.
Неустойчивая строка, TLAST на третьей секции или пятая строка вызывают
`error=1`, `configured=0`, `cfg_ready=s_ready=0` до сброса. Ошибочная загрузка
не откатывается к прежней конфигурации. Незавершённая загрузка ожидает
продолжения или сброса; автоматического таймаута в ядре нет.

Насыщение допустимо и обработку не блокирует; оно устанавливает `saturated`.
Сброс очищает состояния, статусы и ожидающий результат, отменяет частичную
конфигурацию. Во время активного сброса все `ready` и `m_valid` равны нулю.
Поля данных без valid значения не имеют. Операнды, произведения и выходные
регистры данных не имеют инициализаторов и не требуют сброса.

## Архитектура и темп

Два общих signed32×signed18 умножителя обрабатывают I/Q параллельно и
последовательно обслуживают все секции. Операнды и полные 50-битные
произведения зарегистрированы. Одна секция занимает 11 тактов:

```text
LOAD_Y → MULT_Y → ROUND_Y → MULT_B1 → SAVE_B1 → MULT_A1 → UPDATE1
       → MULT_B2 → SAVE_B2 → MULT_A2 → UPDATE2
```

Изменения состояний происходят ровно один раз на принятую пару I/Q.
Новый отсчёт не принимается до потребления предыдущего выхода. Выходной
регистр удерживает данные и TLAST при backpressure; повторных обновлений
рекурсии при остановке нет.

| Секции N | Выход valid после принятия входа | Принятие входа → потребление выхода | Интервал приёма, без пауз |
| --- | ---: | ---: | ---: |
| 1 | 11 тактов | 12 тактов | 13 тактов |
| 2 | 22 такта | 23 такта | 24 такта |
| 4 | 44 такта | 45 тактов | 46 тактов |

Это разрешённое для данной задачи разделение ресурсов по времени, а не
реализация 1 отсчёт/такт. При предположении такта 100 МГц арифметический темп
составляет 7.69/4.17/2.17 млн пар I/Q в секунду. Физическая достижимость
100 МГц не проверялась; переносимый 32×18 умножитель может потребовать
несколько аппаратных DSP. Число DSP и возможности упаковки регистров не
заявляются без синтеза.

## Доказательство разрядностей

Вход `X` лежит в [−2^17,2^17−1], коэффициент `C` — в
[−2^31,2^31−1]. Точный диапазон полного произведения:

```text
−2^48 + 2^17 ≤ C*X ≤ 2^48
```

Положительный край достигается на двух минимальных отрицательных кодах;
49 знаковых бит для него недостаточно, поэтому произведение имеет 50 бит.
После насыщения `y` его диапазон уже входного, поэтому та же граница
безопасна для произведений обратной связи.

Пусть L=2^(B−1)−1 и H=2^(F−1). Для полной выходной суммы:

```text
−L − 2^48 + 2^17 + H ≤ b0*X + S1 + H ≤ L + 2^48 + H
```

Для разности двух произведений достаточно симметричной границы
D=2^49−2^17 (даже если независимо разрешить обоим операндам полный signed18):
`−D ≤ P1−P2 ≤ D`. Поэтому для обновления S1 безопасна граница
`−L−D … L+D`, а для S2 — `−D … D`.

Ядро консервативно выделяет
`AW=max(B,51)+1` бит: при B≤51 это 52 бита, при B=64 — 65 бит.
При B≤51 величина L+D меньше 2^51; при B≥52 она меньше 2^B.
Выходная сумма с H≤2^27 также находится строго внутри этих границ.
Все сложения, вычитания, сдвиги и сравнения насыщения выполняются в AW,
знаковое расширение явно предшествует операции. Ни одна необрезанная
промежуточная величина не переполняет выбранный регистр/провод.
Это безопасная ширина с запасом, а не заявление о минимальной ширине
для каждого возможного набора коэффициентов.

В проверке устойчивости используются signed34: даже при независимых
signed32 `a1,a2` суммы `2^F±a1+a2` лежат внутри
[−2^32+2^16, 2^32+2^28], то есть внутри signed34.
Счётчик конфигурации 3-битный (0…4), число секций — 3 бита (1/2/4),
индекс — 2 бита (0…3), автомат — 4 бита (12 фаз). Пятая строка
отвергается до индексирования; счётчик не оборачивается.

## Запуск и свидетельства

Из корня изолированной копии, новый `--output-dir` обязателен для повторения
приведённых имён; существующий путь отвергается до запуска инструментов:

```bash
python3 tools/run_sos.py --suite all --simulator verilator --output-dir build/rtl/sos_verilator_20261030
python3 -m pytest -q tests/test_sos_rtl.py
```

Доступны `--suite python/lint/hdl/all`, `--simulator questa/verilator`;
по умолчанию симулятор — Questa. Без `--output-dir` создаётся новый каталог
с UTC-меткой времени. `all` включает Python, строгий `verilator --lint-only
-Wall` без waiver и HDL. Синтез ни в одном режиме не вызывается.
Результат `results.json` получает PASS только после проверки всех ожидаемых
счётчиков, отрицательных контролей и `regression_evidence.finish`.
Снимок исходников фиксируется через `begin`, оптимизированный Python
отвергается через `require_unoptimized`. Дополнительный C++-адаптер также
проверяется по SHA-256.

Векторный стенд использует `axis_check.sv` для входа, выхода и конфигурации.
Случайные паузы источника и приёмника воспроизводимы. Отдельно проверяются
длительная остановка последнего выхода, приоритет cfg/data, частичная
конфигурация, ожидающая cfg внутри кадра, сброс на всех 11 шагах обработки
и при непрочитанном результате, сброс частичной конфигурации, ошибочные
длины/полюса и ближайшие допустимые границы устойчивости.

Числовой контроль сравнивает I/Q, TLAST, sticky saturation, каждый выход
секции, ненасыщенные результаты округления, числители состояний и состояния.
Независимая целочисленная
рекурсия в Python-тестах сравнивает все промежуточные значения модели;
SciPy проверяет Butterworth low/highpass 1/2/4 SOS и резонатор.
Испытания включают импульс, ступень/DC, полный signed18 диапазон,
signed32 края коэффициентов, насыщение состояний и длинный нулевой хвост.
Для полюса 0.99 зарегистрирован предельный цикл 49 кодов на нулевом входе;
устойчивость линейного фильтра не гарантирует исчезновение квантованного
предельного цикла. Резонатор r=0.995 после 8000 отсчётов имеет хвост ≤15
кодов и ошибку к SciPy <15 кодов в проверенном профиле.

Числовой отрицательный контроль искажает ожидаемый выход. Протокольный
изменяет реальный удерживаемый вход при `ready=0` и обязан сработать в
`axis_check`. Оба требуют **именно код возврата 13**, свой fatal-тег и
отсутствие PASS. Для Questa код устанавливает `run.do`; для Verilator
`--binary --timing` используется официальный hook `VL_USER_FATAL` из
`sos_verilator_exit.cpp`, так что код 13 возвращает сам процесс симулятора.
Сигнальный crash или произвольный ненулевой код PASS не дают.

В Verilator 5.050 обходится ошибка `%d` для отрицательных чисел шире
64 бит: стенд читает десятичную строку и явно разбирает её в AW бит.
Коды фаз наблюдения заданы локально в стенде: иерархическая ссылка на имя
enum при активном нуле вызывает внутреннюю ошибку этой версии Verilator.
Оба обхода касаются только тестбенча; предупреждения не подавляются.

Фактический прогон 2026-10-30, Verilator 5.050 — **PASS**;
свидетельство: `build/rtl/sos_verilator_20261030/results.json`.

| Проверка | Реальный результат |
| --- | --- |
| `--suite all --simulator verilator` | PASS, код 0 |
| Python внутри all | 22 теста PASS: 8 исходных + 14 новых |
| Отдельный `pytest -q tests/test_sos_rtl.py` | 14 тестов PASS |
| Строгий lint | 12 конфигураций, без предупреждений и waiver |
| HDL | 12 сборок, 24 положительных запуска |
| Побитовые выходы | 1 610 680 пар I/Q, вместе с TLAST и saturation |
| Промежуточные контрольные точки | 11 145 552, плюс сравнение сохранённых состояний |
| Отрицательные контроли | 12 числовых + 12 протокольных, каждый с кодом 13 |
| Полный перебор signed18 | Все 262 144 кода на I и Q; F=28, B=64, обе полярности, с паузами и без |
| Прочие форматы | (F,B)=(28,40),(16,40),(16,64),(22,52),(28,51), обе полярности |
| Измеренный темп N=1/2/4 | Латентность 12/23/45, II=13/24/46 тактов |
| Свежесть свидетельства | `require_pass` PASS: 1658 исходников и 86 артефактов под хешами |

Для каждого сочетания форматов загружаются все 13 основных числовых
профилей; базовый формат дополнительно содержит 32 порции полного перебора.
Суммарные числа выше относятся к положительным прогонам, без прибавления
отменённых сбросом отсчётов из направленных протокольных сценариев.

## Ограничения и передача куратору

Questa в этой среде не запускалась. Синтез Vivado/Quartus/ISE, размещение,
трассировка, физический тайминг и ресурсы не проверялись. Verilator выполняет
двухсостояниевую симуляцию: проверка X/Z в `axis_check` не заменяет будущую
четырёхсостояниевую приёмку Questa. Полная общая
регрессия проекта не запускалась. Применение в кадровом модеме потребует
учёта II, внешнего буфера и требуемой средней частоты входных отсчётов.
Новые коэффициенты следует проектировать и балансировать через модель;
проверка устойчивости не является гарантией запаса до насыщения.

Точная команда Questa-приёмки куратора (новый каталог):

```bash
python3 tools/run_sos.py --suite all --simulator questa --output-dir build/rtl/sos_questa_20261030
```

Общие реестры этой задачей не изменены. Предлагается отдельно зарегистрировать
`run_sos.py` в `tools/run_streaming_rtl.py` и RTL-наборе `tools/run_tests.py`,
добавить `sos_iir` в `rtl/rtl_synth_top.sv` только при возобновлении физической
приёмки, описать модуль/стенд/раннер в соответствующих README и сослаться на
этот документ из `docs/RTL_TODO.md` и `docs/CURRENT_STATUS.md`. Для
`rtl/warnings.json` исключения не требуются. DSP-SOS не следует помечать
физически принятым по результатам функциональной симуляции.

## Приёмка куратором в Questa (2026-10-30)

Questa 2024.1, `python3 tools/run_sos.py --suite all --simulator questa --output-dir build/rtl/sos_questa_20261030` — **PASS**: все конфигурации раннера, обе полярности сброса, сценарии с остановками входа/выхода, численный и протокольный отрицательные контроли с кодом ровно 13; свидетельство `build/rtl/sos_questa_20261030/results.json` с хешами исходников. Перед приёмкой раннер исправлен: аргументы `vsim` (`+VECTORS`, `-do`) передаются относительно рабочего каталога — абсолютные пути с кириллицей приводили к падению Questa (`Bad pointer access`); положительный и отрицательный `.do` разделены, чтобы успешный `$finish` не превращался в код 13. Синтез и физический тайминг не выполнялись.
