# UVM окружение для BPSK RX пилота

С 2026-10-15 окружение TX вынесено в общий `rtl/tb/modem_tx_uvm.svh`; BPSK использует прежние векторы и геометрию `8*N+32`. Отдельная обёртка проверяет [передатчик OQPSK](RTL_OQPSK_UVM.md) с двухбитным входом и хвостом `8*N+36`.

`python3 tools/run_bpsk_uvm.py --suite all` запускает настоящее UVM окружение вокруг ORDER=2 RTL `bpsk_rx`: sequence item/sequence, sequencer, driver, monitor, scoreboard, env и test. Вызов `run_test` расположен в отдельном top. Основная регрессия `run_tests.py --suite all/hdl` без выбора отдельного модема включает этот пилот автоматически и сохраняет его артефакты.

Старый SystemVerilog тестбенч сохранён. Окружение охватывает один BPSK RX; распространение на остальные профили, TX, cross coverage и SER сравнение с вещественным приёмником остаётся в TODO.

## Независимые события и эталон

Sequence загружает оригинальные waveform, numeric trace, acquisition и payload metadata от `receiver_vectors`, передаёт драйверу целые кадры и управляющие транзакции. Драйвер публикует ожидаемый кадр до первого входного слова, меняет контролы на negedge и удерживает каждое предъявленное слово до handshake.

Monitor использует clocking inputs `#1step` на posedge: принимается старое, ещё не изменённое NBA значение valid/ready/data. Только реальные принятые выходы и acquisition события попадают в analysis port. Числовое сравнение охватывает I/Q, фазу/частоту/усиление/поправку, index/label/last. Raw SER считается против исходной переданной метки после 192 символов обучения, без корректировки по payload truth.

Scoreboard отдельно хранит ожидаемые кадры и acquisition. Reset fence приходит от наблюдаемого сброса, удаляет оставшуюся очередь и очищает частичные SER счётчики. Проверяется равенство `checked + discarded == expected`, завершение всех полных кадров, отсутствие лишних результатов и 100 тактов охраны после окончания.

## Сценарии

Stream, задержанный выход, сброс активного кадра и сброс частичной конфигурации выполняются при обеих полярностях: восемь обычных прогонов, по четыре полных кадра. Итоговый payload — 58 ошибок из 2304 символов в каждом прогоне, на тех же четырёх смешанных каналах.

При midreset сначала подаётся 4200 отсчётов существующего шумового frame3 без входного last. Перед сбросом реально принимаются 288 выходов, включая 96 payload symbols и 13 ошибок. Сброс при непринятом выходе отменяет 480 ожидаемых символов. Затем четыре кадра повторяются: суммарно `3360 checked + 480 discarded = 3840 expected`, пять acquisitions, 384 cfg handshakes и 28931 input handshakes. Это упражняет очистку и знаменателя, и числителя частичного SER.

Cfgreset принимает 96 слов незавершённой конфигурации, сбрасывает DUT, затем загружает полные 192. Значения/last сохраняются при backpressure; счётчики требуют реально наблюдённых остановок и сбросов.

## Отрицательные контроли

- NUMERIC повреждает только ожидаемое I.
- SER меняет только одну исходную метку в колонке9; числовая колонка7, waveform/acquisition и отдельный `payload_expected.txt` остаются прежними.
- VALID_X/READY_X принудительно задают X на реальном активном выходном интерфейсе.

Все четыре контроля при двух полярностях дают rc13, соответствующий UVM Fatal и отсутствие успешного summary. Monitor немедленно отвергает неизвестные reset/valid/ready/error/acquisition controls и неизвестные данные при valid, включая задержанный выход.

Независимый аудит обнаружил ложный PASS ранней версии: X на `m_valid` после четырёх кадров проходил 100-тактную охрану и parser. После исправления тот же bind probe завершается `[PROTOCOL]`, rc13, без summary. Before/after исходники и журналы сохранены в `build/rtl/continuation_20261013_sync/uvm_x_control_audit/`. Пять узких Python-тестов проверяют parser, reset accounting, SER mutation и принятие/отказ отрицательных контролей.

## Продолжение: полноценный TX пилот

`bpsk_tx_uvm_tb.sv` добавляет отдельные sequence/sequencer/driver/monitor/scoreboard/env/test. Совместный runner по умолчанию проверяет RX и TX; `--pilot rx/tx` сохраняет отдельные отчёты. TX не имеет cfg ports, поэтому cfgreset объявлен неприменимым.

Пять кадров длиной1/2/33/192/768 символов дают996 принятых входов и8128 выходных отсчётов; число выходов независимо равно сумме8*n+32. Прежние bits.txt/tx.txt сохранены. Десять обычных сценариев stream/gaps/stalled/midreset/outreset охватывают обе полярности. Реально проверено удержание входа/выхода и232 ready-source gaps.

Midreset принимает16 warm symbols и111 выходных отсчётов, затем отбрасывает6065 ожидаемых samples и752 ещё не предъявленных input symbols. Outreset принимает33 warm symbols, наблюдает295 samples и удерживает final TLAST до reset; отбрасывается ровно один sample. Эталонные очереди и монитор настоящих pin handshakes сверяются раздельно, затем полные кадры проходят повторно.

14 TX отрицательных контролей проверяют NUMERIC, неизвестные controls обоих направлений, неизвестные valid data и повреждение удерживаемого выхода. Требуются нужный UVM_FATAL, ненулевой rc и отсутствие завершённой TX summary. Совместный root RX+TX прогон прошёл18 обычных и22 отрицательных случаев;10 parser/reference тестов — PASS. Общий run_tests требует обеих полных BPSK RX/TX серий и всех controls; два теста parent coverage отвергают частичную ложную приёмку.

На момент этой контрольной точки остальные модемы оставались в TODO. Затем приняты [OQPSK/MSK/GMSK RX](RTL_PACKET_RX_UVM.md), их TX и [DSP UVM](RTL_DSP_UVM.md); добавлены [все PSK/QAM TX](RTL_PSK_TX_UVM.md). QPSK_DIFF SIMO и PSK8_FB RX добавлены ранее, floating SER — в разделе ниже. RX BPSK waveform, прежние record keys и core сохранены.

## Продолжение 2026-10-14: floating SER внутри UVM

`tools/uvm_floating_reference.py` — независимый вещественный приёмник (`modem_core.receive`) на тех же raw Q15 pin-строках `rx_wave.txt`/32768. Для QPSK_DIFF SIMO используется `modem_core.maximal_ratio_combine` с реальными Q15 gains и относительными дисперсиями из `gains.txt`. Решения не читают truth; truth используется только для подсчёта ошибок. Fixed-приёмник и fixed-комбайнер не участвуют (тест подменяет все функции модулей `*_fixed` на исключение и получает те же решения).

До создания отрицательных копий на исходных векторах записываются неизменяемые `float_decisions.txt`, `float_expected.txt` (ошибки и знаменатель на кадр) и `float_reference.json` (sha256 входов, решений, ожиданий и исходной truth). Сразу выполняется независимая перепроверка: повторный float прогон, provenance, совпадение решений, счётчиков и знаменателей.

UVM (`+FLOAT_SER`, включён во всех RX прогонах) на каждом реально принятом payload символе сравнивает и RTL метку, и float решение с одной и той же строкой truth. При завершении кадра scoreboard требует совпадения знаменателя с фактическим payload интервалом и float ошибок с неизменяемыми метаданными, печатает `rtl_errors/float_errors/delta`. В check_phase проверяется, что сравнение покрыло каждый завершённый кадр. Прежние NUMERIC/SER/reset/width/gain проверки сохранены.

| Профиль | RTL ошибки по кадрам | float ошибки | delta (RTL−float) | знаменатель |
|---|---|---|---|---|
| BPSK | 0,0,0,58 | 0,0,0,54 | 0,0,0,+4 | 576 |
| QPSK_DIFF SIMO | 0,0,14,277 | 0,0,16,308 | 0,0,−2,−31 | 576 |

Различия видны только на шумовых кадрах и приведены как измерение: фаза не подгоняется по truth, бюджета допустимой разницы нет. На кадре 3 RTL у QPSK_DIFF и PSK8_FB ошибается реже float, у BPSK — чаще.

Новые отрицательные контроли для каждого из трёх RX профилей при обеих полярностях сброса: изменение одного float решения, счётчика ошибок или знаменателя. Каждый даёт `UVM_FATAL [FLOAT_SER]`, rc13 и отсутствие summary (18 прогонов). Независимый валидатор отвергает все 9 изменённых наборов, а также изменения waveform/gains/preamble и truth; при пересчитанных digest его всё равно останавливает повторный float прогон.

Итог в изолированной копии и в root: 34 обычных и 66 отрицательных UVM сценариев (48 прежних + 18 FLOAT_SER), 9 отказов валидатора, PASS. Python: 7 новых тестов `test_uvm_floating_reference.py`, обновлены `test_bpsk_uvm_evidence.py` и `test_uvm_pilot_coverage.py`. Parent `run_tests` требует float сравнения во всех RX записях, FLOAT_SER негативов и отказов валидатора. Diff, исходные копии и журнал: `docs/resume_20261014/float_ser_20261014/`.

### Диагностика разрыва QPSK/QPSK_AXIS (2026-10-14)

Первоначальная гипотеза про проскальзывание в петле слежения не подтвердилась: ошибки идут не со скачка, а почти равномерно по всему кадру, около 75%, то есть угадывание. Кадр 3 — SNR −8 дБ без частотного сдвига и задержки.

Причина — захват fixed-модели, а значит и RTL, которое побитно с ней совпадает. `psk_fixed.acquire` оценивает частоту наклоном развёрнутых фаз отдельных символов. При −8 дБ фаза символа шумит на десятки градусов, разворачивание набирает ложные обороты, наклон получается ложным: у QPSK −34.8M (≈ −0.008 оборота на символ) вместо 0. Когерентная амплитуда с ложным наклоном почти гасится, gain упирается в ограничение `16<<20` = 16777216. Так видно в `rx_acquire.txt`: у QPSK и QPSK_AXIS gain = 16777216, у дифференциальных профилей ≈ 1.47M. Дифференциальные профили переносят остаточный поворот, недифференциальные — нет.

Эксперимент [`blockfit_experiment.py`](resume_20261014/qpsk_gap/blockfit_experiment.py) подставляет уже существующую блочную оценку `fit_blocks`: когерентные суммы по 16 символов, 8 блоков. Сейчас она используется только у QAM16_EQ/DFE. Ошибки на кадре 3:

| Профиль | сейчас | блочная оценка | float |
|---|---|---|---|
| QPSK | 445 | 128 | 144 |
| QPSK_AXIS | 430 | 150 | 151 |
| QPSK_HALF_DIFF | 284 | 230 | 238 |

Кадры 0–2 остаются без ошибок, их частота и gain захвата почти не меняются. В RTL блочная оценка уже есть (`bpsk_acquire` параметр `BLOCK_FIT`), но `bpsk_rx` привязывает её к `EQUALIZER!=0`. Ограничения: диапазон блочной оценки 1/32 оборота на символ против ±1/2 у посимвольной, и `fit_blocks` пока не поддерживает 8-PSK. Включение — решение по алгоритму: меняются принятые векторы и зафиксированные SER этих профилей, а их физическая приёмка остаётся на паузе синтеза.

### Исправление захвата (2026-10-14, по решению пользователя)

Причин оказалось две. Вторую нашли на другом сигнале −8 дБ из отчёта точности (`psk_precision`, 320 символов payload): там блочная оценка не помогла QPSK (242→247 при float 82).

1. **Посимвольный фит частоты.** Для всех ORDER=4 профилей включена блочная оценка (`block_fit=True`). В RTL `bpsk_rx` получил параметр `BLOCK_FIT` со значением по умолчанию `EQUALIZER!=0||ORDER==4`. Блочный сумматор в `bpsk_acquire` раньше был только в ветке QAM; теперь он есть и в ветке ORDER=4. Без него `BLOCK_FIT=1` при ORDER=4 укорачивал фит, но запросы шли посимвольно, и `bpsk_rx_tb` падал по THROUGHPUT.
2. **Отброшенный кандидат задержки (общий для всех профилей).** Грубая задержка по энергии при −8 дБ дала −0.81 отсчёта при истинном 0. Кандидаты `delay+{0,8,16}` вне окна [−0.5; 16.5] отбрасывались. Оставались только 7.19 и 15.19, то есть сдвиг на символ, и фит шёл по шуму. Теперь кандидаты ограничиваются границей окна, в модели и в RTL одинаково. Худший случай по времени (три кандидата) не изменился.

Fixed против float на случае −8 дБ из `psk_precision`: QPSK 242→74 (float 82), QPSK_AXIS 236→124 (96), QPSK_HALF_DIFF 141→112 (118), QPSK_AXIS_DIFF_FF 142→116 (132), QPSK_DIFF 137→112 (118), PSK8_FF 269→228 (228), PSK8_FB 284→232 (234), PSK8_ROTATED_FB 272→239 (223), QAM16 297→259 (270), QAM16_EQ 277→257 (275), QAM16_DFE 279→263 (276). В `oqpsk_mrc_precision` MRC (дисперсии 1,4): 115→60 (56). BPSK, PI4 и QAM64 не изменились. Чистый и номинальный каналы — по-прежнему 0 ошибок.

UVM кадр 3, RTL до→после (float): QPSK 445→128 (144), QPSK_AXIS 430→150 (151), QPSK_HALF_DIFF 284→230 (238), QPSK_AXIS_DIFF_FF 280→242 (302), QPSK_DIFF 277→220 (308), QAM16 552→505 (493), QAM16_DFE 515→507 (521).
