# Подбор разрядности аккумулятора FIR

`fir_runtime` получил параметр `ACC_WIDTH` и проверку допустимости коэффициентов для уменьшенной ширины. `tools/fir_width_sweep.py` выбирает минимальную ширину по точным границам для полного диапазона signed18 входа. Для обычных наборов проекта получено 35–36 бит; прежние значения по умолчанию составляют 39–45 бит. Дробная часть коэффициентов — Q17, вход и выход — Q15. Точная сумма, округление half-up и выходное насыщение сохраняют прежнюю арифметику для принятой конфигурации.

Первый этап подбора относится к аккумулятору, его сумматорам и регистрам результата. Продолжение 19 октября охватывает также произведения и дерево сумм (ниже). Выигрыш ресурсов и физический тайминг требуют проверки в FPGA-инструментах; синтез остаётся на согласованной паузе.

## Компактное дерево сумм: продолжение 19 октября

`COMPACT_TREE=1` по умолчанию задаёт отдельную ширину каждому уровню и каждой компоненте дерева. `COMPACT_TREE=0` оставляет прежнюю одинаковую ширину `37+LOG2LANES` у всех узлов для парного числового контроля. Число ступеней, valid-конвейер, FIFO и порты не меняются.

Пусть `A=2^17`. Для любых signed18 коэффициентов и входных слов точное вещественное произведение лежит в интервале `[-A²+A, A²]`: ему необходимы 36 бит. Комплексная полоса даёт:

```
Re ∈ [-2A²+A, 2A²-A]       — signed36
Im ∈ [-2A²+2A, 2A²]        — signed37
```

Положительный предел Im равен `2^35`, поэтому 36 бит для неё недостаточно. Каждый следующий уровень складывает независимые полосы и добавляет ровно один бит: Re требует `36+level`, Im — `37+level`. Округление в дереве отсутствует; добавка half-up применяется только после аккумулятора. Эти ширины достаточны для любых допустимых коэффициентов без дополнительного ограничения конфигурации. Четыре произведения остаются signed36: уменьшать их без ограничения входов или коэффициентов нельзя.

Массивы каждого уровня содержат только используемые узлы. При 64 полосах прежнее дерево объявляло 10922 бита регистров, компактное — 9511, на 1411 бит (12.9%) меньше. Это подсчёт объявленных слов дерева; он не измеряет реальные FPGA-регистры, LUT, DSP или частоту после синтеза.

Проверяющий монитор `rtl/tb/fir_tree_check.svh` независимо вычисляет ожидаемые произведения и суммы каждого узла из исходных файлов входа и коэффициентов, затем задерживает их до соответствующей ступени. Он не использует операнды, RAM или дочерние узлы DUT как числовой эталон. Проверяются также реальные `$bits` узлов. Отдельные отрицательные контроли `[PRODUCT]` и `[TREE]` портят наблюдаемое значение, поэтому насыщение выхода не может скрыть ошибку.

Матрица `fir_width_sweep.py --verify-rtl` сравнивает компактное и прежнее дерево при выбранной и прежней ширине аккумулятора, обеих полярностях и пяти сценариях сбросов/пауз. Добавлен случай 64 коэффициентов `(-131072,-131072)` с 64 полосами: на полном перекрытии мнимая сумма достигает `2^41` и упражняет старший бит всех уровней. Вместе с прежними наборами это 12 геометрий. Проверка отчёта требует точного числа наблюдённых произведений и узлов, всех шести отрицательных контролей и одинакового числа stream-тактов у парных реализаций.

## Границы и округление

Для каждого комплексного коэффициента `h = hr + j·hi` и отсчёта `x = xr + j·xi`:

```
re = hr*xr − hi*xi
im = hr*xi + hi*xr
xr, xi ∈ [−131072, 131071]
```

Каждая компонента линейна по `xr, xi`, поэтому её минимум и максимум достигаются на четырёх углах этого прямоугольника. Отсчёты при полном перекрытии независимы: покомпонентные экстремумы отдельных отводов складываются. Интервалы содержат ноль, поэтому те же границы покрывают укороченные края кадра, подмножества полос и частичные суммы последовательных шагов.

Минимальный W выбирается из 18…63 так, чтобы одновременно выполнялись условия:

```
min(re, im) ≥ −2^(W−1)
max(re, im) + 65536 ≤ 2^(W−1) − 1
```

Добавка 65536 нужна для существующего `sat18`: округление выполняется как `(acc + 65536) >>> 17` в слове аккумулятора. Для единственного коэффициента 65536 (0.5 в Q17) сырая сумма помещается в signed34, но максимальное входное слово после добавки округления даёт ровно `2^33`. Поэтому безопасная ширина — 35, а конфигурация с 34 отклоняется.

Нижняя граница signed18 асимметрична. Для `T` коэффициентов `(-131072, -131072)` максимальная мнимая сумма равна `T·2^35`. При `T=2^LOG2TMAX` это требует `37+LOG2TMAX` бит. Такая ширина достаточна для любых допустимых коэффициентов и входов, включая добавку округления. Прежний default `38+LOG2TMAX` сохранён как контроль.

## Проверка при конфигурации

При `ACC_WIDTH < 37+LOG2TMAX` RTL на каждом принятом коэффициенте обновляет четыре границы. Умножение на углы входного диапазона реализовано сдвигом и сложением/вычитанием. При последнем коэффициенте проверяются обе компоненты и добавка округления. Если ширины недостаточно, устанавливается sticky `error`, `configured` остаётся нулём, приём данных и новых коэффициентов прекращается до сброса.

Проверка выполняется по всему допустимому входному диапазону, до получения сигнала. Поэтому тихий вход не делает небезопасную конфигурацию допустимой. При достаточной общей ширине проверка сводится к константе: отдельные регистры границ отсутствуют в этой ветви `generate`.

Сброс очищает границы частичной конфигурации. Успешный `cfg_last` завершает их накопление, поэтому следующий набор коэффициентов проверяется независимо от предыдущего. Обычный протокол конфигурации на свободной границе транзакции сохраняется.

## Функциональная проверка первого этапа (аккумулятор)

У каждого сочетания семь кадров: случайный полный диапазон, один отсчёт, импульс и четыре последовательности углов, достигающие минимума/максимума обеих компонент. Сырые суммы независимо вычисляет NumPy convolution на целочисленных входах; произведения и суммы этих наборов точно представимы в complex128. Выходы сверяются также с исходным `fir_fixed.filter`. Все четыре аналитических экстремума должны действительно встретиться в кадрах.

Оба значения ширины получают одни и те же файлы коэффициентов и отсчётов. В Questa сравниваются каждый выход, TLAST, каждая сырая сумма до округления/насыщения, реальные события насыщения, активные индексы, FIFO и резервирование. Пять сценариев — stream, паузы входа/выхода, сброс неполного кадра, сброс после выхода и сброс частичной конфигурации. При обеих полярностях это **220 обычных прогонов**.

Отдельные **42 прогона конфигурационных защит** проверяют выбранную ширину и ширину на бит меньше, повторную загрузку без сброса, сброс незавершённой конфигурации, sticky error и восстановление до работающего FIR с нулевым коэффициентом. Для нулевого набора меньшая ширина выходит за поддерживаемый диапазон, поэтому отдельного отказа W=17 здесь нет. Два отрицательных контроля портят сравниваемую сырую сумму и обязаны завершиться с `[ACCUMULATOR]`; выходное насыщение не может скрыть эту проверку.

Python-тесты проверяют аналитические интервалы исчерпывающим перебором углов небольших FIR, особые случаи минимальных отрицательных коэффициентов и округления, полноту отчёта, запись/чтение JSON и отбрасывание подменённых или неполных свидетельств. Формат отчёта одинаков до и после сериализации.
