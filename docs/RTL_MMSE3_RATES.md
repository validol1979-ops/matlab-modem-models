# MMSE3: реальные отсчёты, тройки и задержки

`python3 tools/run_mmse3_rates.py --suite all` проверяет две унитарные H × две полярности reset × ready1/ready5of8: восемь настоящих RTL-потоков. Каждый содержит 32 кадра по 3072 комплексных отсчёта. Один вектор состоит из трёх передач. Арифметическая проверка использует независимое точное W=Hᴴ, без чтения весов DUT.

| Режим | Центральный вход, отсчётов/такт | Центральный выход, отсчётов/такт | FIFO peak / capacity |
| --- | ---: | ---: | ---: |
| ready1 | 1.000000 | 1.000000 | 3 / 16 |
| ready5of8 | 0.624986 | 0.625010 | 14 / 16 |

Скорость вектора в ready1 — 1/3 за такт. Для ready5of8 входное окно содержит 49152 передачи за 78645 тактов, выходное — столько же за 78642: различие обусловлено границами физических окон. Полный вывод хвоста даёт 98304/98309 и 98304/157289 отсчёта за такт соответственно. Межкадровые границы учитываются отдельно; передатчик непрерывно держит valid.

Девять cfg words приняты на тактах 7…15; configured поднимается на такте 212, через 197 тактов после последней передачи. От последнего входа соответствующей тройки до первого/последнего выхода: 3/5 тактов при готовом выходе, 3…20/5…25 при backpressure. Максимум pending — две тройки; занятые FIFO+reserved slots — 7/16.

CSV содержит каждый такт, настоящие cfg/data/output handshakes и активные индексы. Проверка пересчитывает все знаменатели и переходы, удержание stalled tuples, reset и drain. 12 тестов и пять повреждений настоящей CSV проверяют пропуск/дублирование передачи, число выходов, циклы и reset; каждый CLI-контроль должен отказать с `[RATE]`, ненулевым rc и без PASS. `--validate <results.json>` заново читает все восемь CSV и проверяет хеши.

Это измерение выбранных матриц при lambda0. Оно не доказывает скорость всех конфигураций и физический 100 MHz; core и параметры FIFO не изменены.
