# Точные разрядности ISTFT overlap-add

`stft_synthesis` получил параметры `PRODUCT_WIDTH` и `ACC_WIDTH`. Defaults — 41 бит для произведений и `41+LOG2N−LOG2HOP` для аккумуляторов кольца. При перекрытии R=N/HOP=1/2/4 это 41/42/43 бита вместо прежних 44. Прежние значения `PRODUCT_WIDTH=42`, `ACC_WIDTH=44` остаются допустимыми и используются для сравнения. В контрольном сочетании PRODUCT_WIDTH=42 и ACC_WIDTH=41 старший бит произведения дублирует знак и не используется сумматором. Только для декларации этих произведений документировано локальное исключение Verilator UNUSEDSIGNAL; raw-монитор проверяет все 42 бита. Для default PRODUCT_WIDTH=41 этого лишнего бита нет. Порты, протокол, FFT, reciprocal ROM, дробные форматы и округление выхода не менялись.

## Точные границы

Вложенный `fft_r2sdf` с WIDTH=24 насыщает каждую ступень симметрично до `±(2^23−1)`. Константа MIN равна **1−2^23**, а не −2^23. Отдельная ветка `sat` заменяет точный минимальный двоичный код на эту симметричную границу. Выходное сопряжение мнимой компоненты также остаётся в том же диапазоне.

Для любого signed18 содержимого ROM окна:

```
|u| <= 2^23−1
−2^17 <= W <= 2^17−1
|u*W| <= (2^23−1)*2^17 = 2^40−2^17
```

Обе границы достигаются при W=−131072 и соответствующем знаке u. Произведению достаточно signed41: диапазон `[-2^40, 2^40−1]`. Signed40 уже недостаточен. Это доказательство не требует положительности стандартного sqrt-Hann окна; отрицательные пользовательские окна тоже покрыты.

После INIT все N ячеек кольца нулевые. Каждый кадр добавляет по одному произведению к N последовательным отсчётам. DRAIN дожидается последней записи, затем EMIT выдаёт и очищает HOP ячеек перед переходом к следующему кадру. Противодавление удерживает EMIT и не допускает нового накопления до завершения выдачи. Поэтому один ещё не выданный абсолютный отсчёт содержит не более R вкладов; начальные/хвостовые области содержат меньше. Финальный кадр выдаёт и очищает все оставшиеся R блоков.

```
|acc| <= R*(2^40−2^17) < R*2^40
ACC_WIDTH = 41 + log2(R)
```

Это достаточная и минимальная общая ширина для произвольных допустимых signed18 окон и выходов FFT. Произведения и суммы хранятся точно: округление внутри overlap-add не добавлено. Сохранён прежний широкий путь масштабирования, включая его half-up округление. Неполные/неправильно размеченные спектральные кадры по-прежнему относятся к ошибкам протокола, а не к новым допустимым форматам.

## Объявленная память

| R | Прежняя ширина компоненты | Новая | Экономия бит кольца для N=256 |
| --- | ---: | ---: | ---: |
| 1 | 44 | 41 | 1536 |
| 2 | 44 | 42 | 1024 |
| 4 | 44 | 43 | 512 |

Кольцо содержит `2*N*ACC_WIDTH` бит. Также сужены регистры чтения аккумулятора и операндов масштабирования, произведения — с 42 до 41 бита. Это подсчёт объявлений RTL; реальная упаковка в BRAM/M10K, число LUT/DSP и физический тайминг не измерялись. Синтез на согласованной паузе.

## Проверка сырых произведений и RAM

`istft_width_sweep.py` создаёт эталон из исходных спектров: целочисленный inverse FFT, точные произведения окна и overlap-add по абсолютным индексам. Для каждой записи сохраняются адрес, предыдущая сумма, произведение, новая сумма и число вкладов; отдельно сохраняется каждая финальная сумма до reciprocal scaling. Эталон не берётся из RAM, операндов или арифметики DUT.

Монитор `istft_width_check.svh` сверяет каждую действительную запись RAM, обе компоненты произведения и предыдущей/новой суммы, затем каждое прочитанное значение перед масштабированием. Проверяются физические ширины и полный охват файлов, а также исключённый код −2^23 на выходе inverse FFT. Исходный scoreboard и наблюдатели насыщения проверяют спектры, выходные отсчёты, TLAST и реальные события clipping.

Матрица содержит семь штатных STFT геометрий и три специальных signed-window случая с R=1/2/4. У специальных случаев окно постоянно равно −131072; спектры с четвертьоборотными фазами направляют насыщенный inverse FFT в одну общую позицию перекрывающихся кадров. Обе границы произведения и суммы реально достигаются. Длинные серии проходят более трёх оборотов кольца; два знака и неполное перекрытие финального хвоста проверяются отдельными транзакциями. Окно анализа остаётся стандартным; пользовательская ROM применяется только к синтезу. Генератор сохраняет окно и reciprocal таблицу в локальные бинарные ROM рядом с векторами, в том числе для геометрий, отсутствующих в штатном каталоге. Отдельный тест проверяет число слов, разрядность и точное декодирование этих файлов.

Для каждого случая сравниваются два значения ширины произведения и два аккумулятора при обеих полярностях сброса, с четырьмя сценариями: stream, паузы входа/выхода, сброс неполного кадра, сброс после выхода. Число тактов должно совпадать во всех парных раскладках. Ширины меньше безопасной и выше поддерживаемой отклоняются с `[PARAMETER]`. Отрицательные контроли `[PRODUCT]`, `[ACCUMULATOR]` и `[RAM_READ]` портят наблюдаемое сырое значение и должны завершиться до итогового PASS.

Python проверяет точные signed-углы и минимальность ширин для всех N=4…256, R=1/2/4, достижение полных экстремумов, JSON roundtrip, полноту матрицы и отбрасывание подменённых/неполных свидетельств. Нативный STFT runner требует полную RTL-матрицу, общий Python runner — аналитический отчёт и тесты. OM-LSA использует тот же модуль ISTFT, поэтому его нативные и UVM-проверки выполняются отдельно.

```bash
python3 tools/istft_width_sweep.py
python3 tools/istft_width_sweep.py --verify-rtl --output build/rtl/istft_width_sweep/rtl_results.json
python3 tools/run_stft.py --suite all
python3 tools/run_omlsa.py --suite all
python3 tools/run_tests.py --suite python
```

Без `--verify-rtl` поле `rtl_verified` равно false. Полная приёмка всех модемов и 17 потоковых наборов выполняется отдельно от этого пакета.
