# Точная ширина аккумуляторов PFB

`pfb_analysis` суммирует каждый полифазный компонент отдельно. Коэффициент с индексом `j` попадает только в фазу `j mod M`, поэтому аккумулятору не требуется вместимость для всех `TMAX` коэффициентов. Новый default `ACC_WIDTH` равен:

```
K = ceil(TMAX/M) = 2^max(LOG2TMAX−LOG2M, 0)
ACC_WIDTH = 36 + max(LOG2TMAX−LOG2M, 0)
```

Прежняя ширина `36+LOG2TMAX` остаётся допустимым явным значением параметра и используется как контроль. При меньшем значении, чем новая безопасная граница, или ширине больше 63 симуляция завершается с `[PARAMETER]`. Ограничение проверяется статически; коэффициенты и входной signed18 диапазон не ограничиваются дополнительно. Конфигурация, Q17 коэффициенты, Q15 вход, Q19 выход, FFT, число ступеней и интерфейсы сохраняют арифметику и протокол.

## Почему этой ширины достаточно

Для вещественного signed18 коэффициента `h` и компоненты входа `x`:

```
h,x ∈ [−131072, 131071]
h*x ∈ [−2^34+2^17, 2^34]
acc ∈ [K·(−2^34+2^17), K·2^34]
```

Минимум и максимум произведения находятся на углах прямоугольника входов. Произведения разных отводов независимы; при полном перекрытии все K экстремумов достигаются одновременно. Для меньшего числа отводов или начала кадра эти же границы достаточны, так как интервал каждого слагаемого содержит ноль. При `TMAX<M` активная фаза содержит не более одного произведения.

Положительный предел равен степени двойки. Ширина на бит меньше новой границы уже не представляет `K·2^34`. Новый default вмещает также добавку 4096 перед сдвигом на 13 бит в `sat22`: `K·2^34+4096` меньше верхнего signed-предела. Точность произведений signed36 не меняется; округление производится только после накопления, как прежде.

| Каналов M | TMAX | Слагаемых в фазе K | Прежняя ширина | Новая ширина | Сокращение объявленных бит аккумуляторов |
| --- | ---: | ---: | ---: | ---: | ---: |
| 4 | 64 | 16 | 42 | 40 | 16 |
| 8 | 64 | 8 | 42 | 39 | 48 |
| 16 | 128 | 8 | 43 | 39 | 128 |
| 64 | 256 | 4 | 44 | 38 | 768 |
| 16 | 4 | 1 | 38 | 36 | 64 |

Считаются два аккумулятора на каждую фазу: `2*M*ACC_WIDTH`. Эти числа не измеряют реальные FPGA-регистры, LUT, DSP или частоту. Синтез остаётся на согласованной паузе.

## Независимая проверка до насыщения

`pfb_width_check.svh` на каждом действительном переносе фаз в FFT пересчитывает сырые суммы из исходных файлов коэффициентов и входных отсчётов. Положение кадра следует TLAST файла, момент выдачи — исходной децимации; проверяется совпадение с `cur_end`. Операнды DUT, его произведения и RAM не используются как числовой эталон. Проверяются обе компоненты всех M аккумуляторов до округления и насыщения, их физическая ширина `$bits`, число наблюдений и полный проход файлов.

`tools/pfb_width_sweep.py` сравнивает выбранную и прежнюю ширину на одних файлах: восемь штатных геометрий и три специальных. Два специальных набора заполняют все TMAX коэффициентов словом −131072 при M=4/64, TMAX=256; третий проверяет M=16, TMAX=4. Три входных кадра специальных наборов содержат обе полные шкалы и одиночный отсчёт. Они действительно достигают обеих аналитических границ до насыщения. Выходной эталон — прежний `pfb_fixed.analyze`; существующие наблюдатели проверяют реальные события насыщения фаз и вложенного FFT.

У каждой геометрии две ширины, две полярности сброса и пять сценариев: непрерывный источник, паузы входа/выхода, сброс неполного кадра, сброс после выхода и сброс частичной конфигурации. Число тактов парных ширин обязано совпадать в каждом сценарии. Ширина на бит меньше безопасной и ширина 64 должны завершиться с `[PARAMETER]` при обеих полярностях. Два отрицательных контроля портят наблюдаемую сырую сумму и должны завершиться с `[ACCUMULATOR]`; выходное насыщение не может скрыть ошибку.

Python проверяет углы signed18 произведений, достаточность/минимальность с учётом округления для M=4…256 и LOG2TMAX=0…16, точное число отводов в каждой фазе, сохранение JSON и отказ при неполном/подменённом свидетельстве. Обычная Python-регрессия включает тесты и аналитический отчёт. Нативный PFB runner требует полную RTL-матрицу, пересчитывает её полноту и проверяет хэши; этот гейт входит в потоковую регрессию через PFB.

## Команды

```bash
python3 tools/pfb_width_sweep.py
python3 tools/pfb_width_sweep.py --verify-rtl --output build/rtl/pfb_width_sweep/rtl_results.json
python3 tools/run_pfb.py --suite all
python3 tools/run_tests.py --suite python
```

Без `--verify-rtl` поле `rtl_verified` равно `false`. Этот отчёт не подменяет RTL-проверку. Полная приёмка всех модемов и потоковых наборов выполняется отдельно от целевой проверки PFB.
