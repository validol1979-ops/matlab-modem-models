# LDPC и GF(2): независимые решения и posterior

`python3 tools/ldpc_precision.py` измеряет 23 случая: четыре режима декодера на clean, AWGN 4 dB, около порога −2 dB и двух видах ограничения, плюс три точные проверки кодирования GF(2). Общие входы — signed16 Q8 LLR, двоичная H и реально загруженные alpha/beta. Float flooding имеет собственные состояния без ограничения; переданные слова используются только для подсчёта ошибок.

Sum-product использует аналитическую phi в логарифмической области. Независимый аудит обнаружил потерю точности прежней формулы около LLR 35; исправленная кусочная формула проверена на 11 аналитических точках с максимальной ошибкой 7.11×10⁻¹⁵. Нулевой вход даёт нулевое сообщение; искусственного верхнего ограничения нет.

Clean BER равен нулю. При 4 dB fixed/float BER совпадает: 0.00390625 для режимов 0/1/3 и 0.00260417 для normalized min-sum. RMS различия posterior после общей одной итерации не превышает 0.06215 единицы LLR. Около порога BER составляет 0.165–0.184; времена остановки могут различаться, поэтому terminal posterior и общая первая итерация измерены отдельно.

Rail stress вызывает реальные ограничения и не получает отметку обычного качества. Точный GF(2) эталон — самостоятельное произведение двоичных матриц. Проверка отчёта связывает bits со знаком terminal posterior, заново считает syndrome/BER/FER и требует остановки после первой итерации, если её syndrome уже нулевой. Составные подмены идеального BER и лишней итерации теперь отклоняются.

Девять тестов проверяют формулы, независимость, форматы, отрицательные контроли и свежесть evidence. Это точность Python моделей; изменение RTL разрядностей и физическая приёмка остаются в TODO.
