# UVM приёмников OQPSK, MSK и GMSK

`python3 tools/run_packet_rx_uvm.py --suite all` проверяет настоящие `oqpsk_rx` и `cpm_rx` (`GMSK=0/1`) через UVM sequence/sequencer/driver/monitor/scoreboard/env/test. Общий `run_tests.py --suite all/hdl` требует все три профиля. Выбор `--profile oqpsk/msk/gmsk` служит локальной диагностике и не принимается родительским гейтом за полный набор.

В `bpsk_rx_uvm_tb.sv` добавлена ветка `PILOT_PACKET`. OQPSK сохраняет двухбитные метки и 18-битные I/Q; CPM сверяет весь знаковый 36-битный `m_value`. Поля, которых нет на контактах этих DUT, явно обнулены адаптером. Общий RX-монитор теперь сравнивает каждый принятый входной отсчёт с sequence, а также принятые конфигурационные метки, захваты и выходные символы. Clocking inputs с `#1step` фиксируют данные до рабочего фронта. Assertions проверяют удержание конфигурации, входа и выхода при backpressure.

## Векторы и SER

Сохранены первые четыре исходных channel cases `oqpsk_cases`/`cpm_cases`: кадры по 768 символов, включая преамбулу из 192 символов, обычный канал, два канала с усилением/фазой/частотой/дробной задержкой и шумовой кадр −8 дБ. Добавляемый генератором OQPSK отдельный overload-кадр исключён из этого SER-эксперимента. Первые четыре волны и truth не меняются.

На каждом принятом payload-символе табло сравнивает фактическую метку DUT с исходной переданной меткой. Знаменатель каждого полного кадра — 576. Float-решения получаются независимо на тех же Q15 pin waves и той же публичной преамбуле; truth читается после декодирования только для подсчёта ошибок. OQPSK/MSK используют `modem_core.receive`, GMSK — независимый `cpm_precision.floating_coherent` с вещественным захватом и Laurent C0. Последний не вызывает `gmsk_coherent.acquire`, который использует fixed acquisition.

Неизменяемые файлы float decisions/errors/denominators и их происхождение повторно проверяет отдельный валидатор. UVM печатает по каждому кадру actual RTL errors, float errors, delta и фактический знаменатель. Различие измеряется без подгонки допуска. Отдельная неизменяемая таблица ошибок каждого префикса исходного шумового кадра проверяет частичную нагрузку при сбросе.

## Сценарии

Все шесть сценариев выполняются при обеих полярностях сброса для каждого из трёх профилей.

| Сценарий | Проверка |
| --- | --- |
| stream | Четыре кадра подряд без сброса |
| stalled | Детерминированное противодавление на выходе |
| gaps | Паузы источника и противодавление; считаются действительные source gaps |
| midreset | 5600 принятых отсчётов исходного шумового кадра, ожидающий выход, сброс и полный повтор |
| outreset | Полный шумовой вход, удерживаемый последний символ с TLAST, сброс и полный повтор |
| cfgreset | 96 принятых меток незавершённой конфигурации, сброс и полная конфигурация |

Табло учитывает принятые и отброшенные входные/выходные очереди. `outreset` обязан отбросить ровно один ожидаемый выход, сохранив доказательство 767 принятых символов и 575 payload symbols до сброса. `midreset` проверяет фактическую длину префикса и ошибки по неизменяемой таблице. Оба сценария требуют ровно одного сброса ожидающего выхода и полного повторного приёма всех кадров.

Всего 36 обычных сценариев. На каждую полярность приходится 18 отрицательных контролей OQPSK и по 19 MSK/GMSK: числовое расхождение, отдельно захват и старший бит метки, X на шести controls, X на выходе/захвате, повреждение удерживаемого выхода и входного отсчёта, исходной truth, partial truth и трёх float-полей; для CPM дополнительно нарушается индекс инкремента захвата. Всего 112 отрицательных прогонов и девять отказов независимого float-валидатора. Требуются правильный `UVM_FATAL`, ненулевой rc и отсутствие успешной summary.

## Исправление GMSK при переходе между кадрами

Детерминированный `stalled` выявил ошибку второго захвата при неизменённых исходных векторах. До исправления получено `(delay, frequency, phase) = (0, 712312, 212133361)` вместо `(147367, 642923, 262461949)`. Монитор принадлежности токенов показал: новый pass1 начинается с инкремента 34, хотя должен начинаться с 0. Старые data-токены неиспользуемого дискриминатора GMSK оставались в общем CORDIC при остановках и попадали в следующий pass1.

`cpm_rx` теперь подаёт в этот CORDIC только нужные токены: pass1 для обоих режимов и data для MSK. Когерентная data-ветка GMSK имеет собственный CORDIC. Дискретная арифметика и модель не менялись.

`cpm_acquisition_check.sv` проверяет последовательность 0…1041 каждого pass1 и требует ровно 4168 проверок для четырёх полностью принятых кадров после последнего сброса. Контроль `INJECT_ACQ_EPOCH` повреждает реальный tag CORDIC и обязан дать `ACQ_EPOCH`. Исходный RTL, журналы обоих отказов и хэши прежних векторов сохранены в `docs/resume_20261015/gmsk_backpressure/`.

Физические тайминги изменённого `cpm_rx` нужно подтвердить после снятия паузы синтеза. Передатчики CPM, FFT и все 128 конфигураций [DSP UVM](RTL_DSP_UVM.md) затем прошли приёмку e; [свидетельство](rtl_uvm_continuation_20261015e_results.json).
