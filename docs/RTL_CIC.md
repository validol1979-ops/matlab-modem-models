# DSP-CIC-DEC: комплексный CIC-дециматор

Реализация: `rtl/common/cic_decimator.sv`. Числовой контракт задаёт неизменённый
`common/python/cic_model.py:CICDecimator`. Тонкая обвязка
`common/python/cic_rtl_cases.py` строит ожидаемые слова через независимый
`cic_reference.decimate_reference` (N свёрток boxcar и downsample), независимо
выполняет wrap и рациональное округление, затем сверяет их с fixed-моделью.
Существующие модемы и общие реестры не изменяются.

## Интерфейс и параметры

Один домен `clk`, синхронный `rst`; активный уровень задаёт `RESET_ACTIVE=1/0`.
Передача на фронте происходит только при `valid && ready`.

| Порты | Значение |
| --- | --- |
| `cfg_valid/cfg_ready`, unsigned `cfg_rate[5:0]` | Одно слово конфигурации, R=1…MAX_RATE |
| `configured` | Есть принятая допустимая конфигурация; после сброса равен 0 |
| `s_valid/s_ready/s_last`, signed `s_re/s_im[17:0]` | Комплексный вход |
| `m_valid/m_ready/m_last`, signed `m_re/m_im[OUT_WIDTH-1:0]` | Прореженный комплексный выход |
| `error` | Залипающая ошибка R или преждевременного TLAST, снимается только reset |

| Параметр | По умолчанию | Допустимо |
| --- | --- | --- |
| `STAGES` | 3 | 1, 2, 3, 5 |
| `DELAY` | 1 | 1, 2 |
| `MAX_RATE` | 32 | 1…32 |
| `ACC_WIDTH` | `18+$clog2((MAX_RATE*DELAY)**STAGES)` | 18…128 |
| `NORMALIZE` | 0 | 0 — raw, 1 — нормировка |
| `RESET_ACTIVE` | 1 | 0, 1 |
| `OUT_WIDTH` | `NORMALIZE ? 18 : ACC_WIDTH` | Обязан совпадать с этой формулой |

Вход — целочисленные знаковые коды. Для принятого в проекте Q18/15 число
дробных бит на выходе также 15: raw содержит усиление фильтра, normalized
делится на G=(R·M)^N. При `NORMALIZE=0` результат — signed ACC_WIDTH без
округления. При `NORMALIZE=1` вычисляется точно
`floor((2*v+G)/(2*G))`, затем signed18 saturation: точная середина округляется
к +∞, включая отрицательные значения. Нормируется уже обёрнутый raw-результат.
Уменьшенная вручную ACC_WIDTH не восстанавливает потерянный диапазон.
Числовой wrap и насыщение являются частью модели и не устанавливают `error`.

## Обмен, TLAST, сброс и ошибки

Интегратор ступени k использует **обновлённую** ступень k−1 того же принятого
отсчёта. Фаза считает принятые входы, а не такты. Выход формируется на входных
индексах R−1, 2R−1, …; comb обновляется только при завершении R-группы.
Каждая ступень comb хранит свои последние M **входов** этой ступени.
Хвост свёртки не выдаётся.

Транзакция заканчивается принятым `s_last=1` на конце полной R-группы.
`m_last` копирует эту метку на соответствующем единственном выходе. Числовое
состояние между транзакциями сохраняется. Следующая транзакция может идти
без конфигурации и без разрыва потока. `s_last` внутри неполной группы
принимается как ошибочная передача: интеграторы, comb, фаза и признак
открытого кадра не изменяются; устанавливается `error`, сбрасывается
`configured`. До reset новые данные и конфигурация не принимаются.

`cfg_ready` разрешён только вне открытого кадра и при пустом выходном
регистре. Пауза источника внутри кадра и непрочитанный последний результат
не разрешают конфигурацию. Принятая конфигурация очищает числовое состояние
и фазу даже при прежнем R. Недопустимые R=0 или R>MAX_RATE дают залипающую
ошибку и `configured=0`; числовое состояние не меняется. Готовый результат
предыдущей группы разрешается дочитать после ошибки. Выход сохраняет свои
valid/data/last до приёма или reset.

При `cfg_valid && cfg_ready` всегда `s_ready=0`; `s_ready` не зависит от
`s_valid`. Ожидающий, но ещё недопустимый cfg внутри кадра не препятствует
прохождению данных. Источники всех трёх каналов обязаны удерживать valid и
слово при valid && !ready.

Reset на фронте очищает числовое состояние, фазу, configured, error и valid;
отменяет входную транзакцию и непрочитанный выход. Выходные data/last не
сбрасываются и значимы только при valid. При активном уровне reset ready
обоих входов и выходной valid комбинационно равны нулю. Рабочий поток
после reset требует новой конфигурации.

## Латентность и темп

Один удерживающий выходной регистр. Без остановок между фронтом принятия
завершающего группу входа и фронтом потребления его выхода проходит **один
такт**. От первого принятого входа группы до потребления результата — R
тактов при непрерывном входе. Вход принимает **1 комплексный отсчёт/такт**,
выход — 1/R отсчёта/такт, при R=1 также 1/такт. Одновременные выдача старого
результата и запись нового разрешены.

При занятом выходе и `m_ready=0` приём всех входов останавливается; все
состояния фильтра удерживаются. Это консервативная политика backpressure,
без внутреннего FIFO и без накопления частичной группы за занятым выходом.
Комбинационная цепочка содержит N сумматоров и N вычитателей; в режиме
нормировки также комбинационный целочисленный делитель. Физический темп
100 МГц не установлен симуляцией.

## Точные границы разрядностей

Для x ∈ [−2^17, 2^17−1] FIR-ядро CIC имеет неотрицательные целые коэффициенты
с суммой G=(R·M)^N. Поэтому его точный выход находится в
[−2^17·G, (2^17−1)·G]. Минимальная общая ширина, покрывающая этот диапазон
для всех R≤MAX_RATE, равна
`18+ceil(log2((MAX_RATE*M)^N))`; ceil(log2(G)) вычисляется целочисленно
как `$clog2(G)`. Максимальное законное G=64^5=2^30 укладывается в signed32
при вычислении параметра, конфигурационное G хранится в unsigned31.

При MAX_RATE=32 ширины по умолчанию:

| N | M=1 | M=2 |
| --- | ---: | ---: |
| 1 | 23 | 24 |
| 2 | 28 | 30 |
| 3 | 33 | 36 |
| 5 | 43 | 48 |

Сами интеграторы на бесконечном потоке не ограничены усилением FIR. Они
намеренно работают modulo 2^W. Их регистры и каждый элемент comb имеют
ровно W=ACC_WIDTH бит с диапазоном [−2^(W−1), 2^(W−1)−1]. Точная сумма двух
таких кодов лежит в [−2^W, 2^W−2], точная разность — в
[−2^W+1, 2^W−1]; присваивание оставляет W младших бит. Эти потери переносов
намеренны. Все операции +/− совместимы с редукцией modulo 2^W, поэтому
каскад даёт ту же редукцию независимой точной FIR-свёртки даже после
многократных переполнений интеграторов. При ширине по умолчанию окончательный
raw FIR-выход помещается точно; при меньшей ширине выход тоже оборачивается.

Для нормировки QW=max(W+2,33). При v ∈ [−2^(W−1),2^(W−1)−1],
1≤G≤2^30 числитель `2*v+G` лежит в
[−2^W+1, 2^W−2+2^30], знаменатель `2*G` — в [2,2^31]. Оба помещаются
в signed QW, как и частное с поправкой для отрицательного остатка.
SystemVerilog `/` усекает к нулю: при отрицательном числителе и ненулевом
остатке из частного вычитается 1, что реализует Python floor division.
После сравнения с −131072/+131071 выполняется единственное насыщение.

R и фаза хранятся в 6 битах: R=1…32, рабочая фаза=0…R−1, её увеличение
не превышает 31. Конфигурационная шина также кодирует все недопустимые
значения до 63, которые отвергаются. История содержит 2·N·M слов W бит,
интеграторы — 2·N слов. Это небольшие регистровые массивы, не BRAM;
при максимальных N/M/W=5/2/128 числовое состояние занимает 3840 бит.

Код использует плоские порты, always_ff/always_comb и статические циклы,
не содержит vendor IP/примитивов, latch, real, начальной инициализации
рабочих регистров или дополнительных тактовых доменов. `initial` проверяет
только допустимость параметров.

## Проверка и команды

Из корня проекта, каждый раз в новый каталог:

```sh
python3 tools/run_cic.py --suite all --simulator verilator --output-dir build/rtl/cic_verilator_20261030
python3 -m pytest -q tests/test_cic_rtl.py
```

Раннер поддерживает `--suite python/lint/hdl/all`, `--simulator questa/verilator`
(по умолчанию questa), `--output-dir`. Существующий каталог отвергается до
запуска проверок. `results.json` хранит RUNNING/PASS/FAIL, параметры, результаты,
хеши исходников и артефактов через regression_evidence begin/finish;
`require_unoptimized` отвергает Python -O. Дополнительный C++ fatal-handler
сверяется в начале/конце и включается в хеши артефактов, поскольку общий
список source_hashes не включает `.cpp`.

`rtl/tb/cic_decimator_tb.sv` запускает 18 независимых worker:
16 сочетаний N/M/нормировки с полной шириной и два W=18 для N=5/M=2.
Все R=1…32 проверяются на impulse, DC, alternating, signed rails и
детерминированных случайных значениях всего signed18-диапазона. Это не
исчерпывающий перебор всех 262144 кодов. В каждой записи два кадра без
очистки состояния, проверяются число/фаза/TLAST. Дополнительная запись
с нечётными суммами при R=2 проверяет положительные и отрицательные half ties.
Ожидаемые слова загружаются отдельно от входов, scoreboard сравнивает только
реально принятые выходы. Проверяются отсутствие лишних слов, один такт
задержки и непрерывное принятие входа без остановок.

Направленные сценарии покрывают одновременные cfg/data с s_valid=0/1,
ожидание cfg в открытом кадре и за непрочитанным выходом, возобновление
ожидающей конфигурации, повторную конфигурацию, reset внутри группы и при
остановленном выходе, R=0/33/63, атомарный отказ TLAST с непустыми
интеграторами и залипание ошибок. Векторный прогон после этих сбросов
проверяет восстановление нулевого состояния. Псевдослучайные паузы источника
и приёмника дополнены длинными остановками выхода; счётчики требуют
фактического backpressure для каждого профиля. `axis_check.sv` контролирует
вход, выход и конфигурацию, включая valid/data/last во время остановки.

Численный отрицательный контроль меняет одно ожидаемое слово. Протокольный
контроль меняет входные данные во время valid && !ready и обязан упасть
именно в axis_check. Каждый контроль принимается только при возврате **13**,
соответствующем NUMERIC/PROTOCOL fatal-теге и отсутствии итогового PASS.
Для `--binary --timing` документированный Verilator hook `VL_USER_FATAL`
в `rtl/tb/cic_verilator_fatal.cpp` печатает диагностический текст и завершает
процесс с кодом 13. Questa использует `onerror/onbreak {quit -code 13}`.
Синтезируемое ядро от этого механизма не зависит.

## Результаты и ограничения

Финальный прогон от 2026-10-30, Verilator 5.050: **PASS**.
Свидетельство: `build/rtl/cic_verilator_20261030/results.json`.

- Python: 43 теста (16 существующих модельных и 27 тестов RTL-обвязки/раннера).
- Генерация: 18 файлов, 2898 записей, 760464 входа, 46152 ожидаемых выхода.
- Строгий `verilator --lint-only -Wall`: 44 конфигурации, без предупреждений
  и без waiver; включая обе полярности, W=18/128 и MAX_RATE=1/3/31.
- HDL: 2 полярности × 2 сценария (непрерывный/со случайными паузами) ×
  18 профилей = 72 прогона профиля; **184608** комплексных выходов побитно,
  **3041856** принятых численных входов, **11592** векторных записей.
- На каждом непрерывном профиле 42087 пар соседних принятых входов;
  расстояние от завершения группы до потребления выхода всегда один такт.
- Все профили stalled-прогона реально испытывали остановки входа и выхода.
- 4 отрицательных запуска: NUMERIC и PROTOCOL при обеих полярностях,
  каждый завершился именно с **кодом 13** и ожидаемым fatal-тегом.
- Отдельный `python3 -m pytest -q tests/test_cic_rtl.py`: **27 passed**.

Журналы компиляции/симуляции, векторы и C++ fatal-handler включены в хеши
артефактов. Изменение исходников требует нового запуска в новом каталоге.

Синтез Vivado/Quartus/ISE не выполнялся. Ресурсы, размещение, 100 МГц и
переносимость по результатам вендорных компиляторов не подтверждены.
Questa здесь не запускалась; ветка Questa подготовлена для приёмки куратором.
Параметры ACC_WIDTH=128 и нестепенные MAX_RATE=1/3/31 охвачены lint;
численная HDL-регрессия использует MAX_RATE=32 и W=18…48. Verilator
не заменяет четырёхзначную симуляцию X в Questa. Полная проектная регрессия
и интеграция с готовыми модемами не выполнялись.

Команда Questa-приёмки для куратора (новый каталог):

```sh
python3 tools/run_cic.py --suite all --simulator questa --output-dir build/rtl/cic_questa_20261030
```

## Приёмка куратором в Questa (2026-10-30)

Questa 2024.1, `python3 tools/run_cic.py --suite all --simulator questa --output-dir build/rtl/cic_questa_20261030` — **PASS**: все конфигурации раннера, обе полярности сброса, сценарии с остановками входа/выхода, численный и протокольный отрицательные контроли с кодом ровно 13; свидетельство `build/rtl/cic_questa_20261030/results.json` с хешами исходников. Перед приёмкой раннер исправлен: аргументы `vsim` (`+VECTORS`, `-do`) передаются относительно рабочего каталога — абсолютные пути с кириллицей приводили к падению Questa (`Bad pointer access`); положительный и отрицательный `.do` разделены, чтобы успешный `$finish` не превращался в код 13. Синтез и физический тайминг не выполнялись.
