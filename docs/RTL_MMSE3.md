# MMSE 3×3 и исправления MMSE 2×2

`rtl/common/mmse3.sv` расширяет библиотеку до n = 3. Эталон — `common/python/mmse3_fixed.py`; запуск — `python3 tools/run_mmse3.py --suite all`. Параметризованный решатель для 2≤N≤8 описан в [RTL_MMSE_N.md](RTL_MMSE_N.md). Синтез, ресурсы и физический тайминг нового блока ожидают возобновления вендорной проверки.

## Арифметика

Вычисляется `(HᴴH + λI)⁻¹Hᴴ`. Конфигурация содержит девять комплексных элементов H по строкам; `cfg_last` и unsigned Q30 λ относятся к девятому слову. Матрица Gram, кофакторы, определитель и веса вычисляются целочисленно, по одному элементу за такт, с последовательной нормализованной обратной величиной.

| Величина | Разрядность компоненты | Дробные биты |
| --- | ---: | ---: |
| H, вход и выход | signed 18 | 15 |
| λ | unsigned 34 | 30 |
| Gram: арифметика / хранение | signed 38 / signed 40 | 30 |
| Кофакторы / adjugate: арифметика / хранение | signed 81 / signed 84 | 60 |
| Действительный определитель: арифметика / хранение | signed 126 / signed 128 | 90 |
| `M = adj(G)Hᴴ`: арифметика / хранение | signed 104 / signed 106 | 75 |
| Веса | signed 64 | 24 |
| Выходной dot product | signed 84 | 39 |

По умолчанию `GRAM_WIDTH=38`, `SUM_WIDTH=84`; допустимы соответственно 38…40 и 84…85 бит. Прежние ширины арифметики воспроизводятся параметрами `GRAM_WIDTH=40`, `SUM_WIDTH=85`. Регистры Gram сохраняют 40 бит, а округление выходной суммы использует дополнительный бит: 85 бит при `SUM_WIDTH=84`. Широкий эталон `common/python/mmse3_fixed.py` оставлен без изменений: его выходной аккумулятор по-прежнему signed 85. Доказательства границ и сравнительная проверка ширин описаны в [RTL_MMSE3_WIDTHS.md](RTL_MMSE3_WIDTHS.md).

Для `Z = 22 + bit_length(det)` используется 24-битное слово `R = round_even(2^Z/det)` с нормализованной величиной от `2^22` до `2^23` включительно. Веса масштабируются half-up сдвигом `Z−39`; нулевой сдвиг точен, отрицательный — точный левый сдвиг. `SCALE_WIDTH=145` покрывает произведение, округление и полный левый сдвиг; прежние 156 бит доступны параметром. Signed64 overflow проверяется до усечения. Неположительный/недействительный определитель и переполнение веса приводят к `error=1`, `configured=0`. Границы и приёмка — [RTL_MMSE_SCALE_UPDATES.md](RTL_MMSE_SCALE_UPDATES.md).

Параметры `ADJ_WIDTH=81`, `DET_WIDTH=126`, `M_WIDTH=104` сокращают вычисления при прежнем хранении; доказательства и сравнения — [RTL_MMSE3_CONFIG_WIDTHS.md](RTL_MMSE3_CONFIG_WIDTHS.md). Масштабирование весов в этом этапе сохранено.

`norm_reciprocal` автоматически выбирает не меньше семи бит для показателя. Случай H = diag(−4−4j) даёт Z = 128 и проверяет восьмой бит; прежние пользователи WIDTH = 40/51/76 сохраняют семибитный интерфейс.

## Поток и отказы

Одна тройка входов даёт y0, y1, y2. `s_last` допустим на третьем входе; `m_last` соответствует третьему выходу последней тройки. Три места в FIFO на 16 слов резервируются на первом входе тройки. Проверены одновременная запись трёх результатов и чтение одного, перенос указателей и отмена неполной тройки.

При готовом выходном потребителе тестбенч требует принятия каждого очередного отсчёта, включая границу кадров. Конфигурация получает приоритет на свободной границе и принимается после завершения входного кадра и полного освобождения FIFO/конвейера. Ошибочная конфигурация и ранний TLAST блокируют продолжение до сброса.

Восемь наборов матриц охватывают identity, комплексный канал, регуляризованную вырожденную матрицу, tiny identity с компонентой 1 LSB, нулевой сдвиг, минимальную мнимую компоненту −131072, случайную комплексную матрицу и Z = 128. Для обеих полярностей и пяти режимов потока/сброса выполняются 80 нормальных симуляций. Сверяются все девять комплексных весов, каждый выход и реальные pre-clamp операции шести ограничителей. Инъекции неверного веса, выходного значения, события, числа вычислений и индекса обязаны завершаться ошибкой и ненулевым кодом.

Отдельно проверены вырожденная H без регуляризации, неверная длина конфигурации, коэффициент вне 64 бит и TLAST на первом/втором входе. Контроль второго входа проверяет освобождение уже занятой резервной тройки; отключение `cancel` воспроизведённо отвергается этим контролем.

## MMSE 2×2

На H = I/32768 существующие модели требовали отрицательного сдвига веса: Python выдавал `negative shift count`, RTL вычитало величину в unsigned поле. Добавлены точные нулевой/левый сдвиги. Для этого случая `W = diag(2^39)` и наблюдение 1 LSB даёт выход 32768 в Q15.

Найдена также тихая потеря старших битов веса при допустимой signed 18-bit H, например raw `[[131071,131070],[1,1]]`. Теперь Python и RTL явно отвергают веса вне signed 48-bit Q24; RTL проверяет полный результат до усечения.

Независимые интерфейсные пробы выявили зависание при совместном приёме первого cfg/data, допуск конфигурации внутри открытого кадра/непрочитанного FIFO и продолжение после ошибочного TLAST первого входа. Конфигурация теперь учитывает границу кадра и освобождение выхода, а неполная пара отменяется с ошибкой до сброса. Правильные прежние векторы сохранены.

Подробности конфигурационного счётчика MMSE 2×2, границ входного формата и общего протокольного прогона — [RTL_CONFIGURATION_PROTOCOL.md](RTL_CONFIGURATION_PROTOCOL.md).
