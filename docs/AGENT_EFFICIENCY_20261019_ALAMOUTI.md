# Luna: точные границы Alamouti

По предпочтению пользователя учитывать уровень агента Codex 6 Luna (`gpt-6-luna`, `luna_alamouti_bounds`) получил read-only задачу по двум файлам: сопоставить четыре формулы Alamouti и перебрать 256 углов восьми signed18 переменных. Архитектура, изменения RTL, независимый монитор и приёмка остались у основного агента.

Агент правильно нашёл границы всех четырёх сумм, общую минимальную signed ширину 38, unsigned ширину энергии 37 и достаточность signed36 для отрицания любого произведения signed18×signed18. Он дал конкретные углы, достигающие границ. Дополнительная арифметическая задача подтвердила signed61 для масштабирования с добавкой округления и достижимый контрпример для signed60. Основной агент независимо проверил формулы и включил их в тесты/сырые RTL-мониторы.

По отчёту Luna первый этап потребовал три вызова exec, один из них пустой. Это лишнее обращение не принесло полезной проверки. Дополнительный расчёт не менял файлов. Достоверные длительность, токены и стоимость отдельного запуска не измерены. Ошибочных арифметических выводов в заданной области не обнаружено; такой результат не подтверждает самостоятельную интеграцию, делитель/синтез агент не проверял.

Сравнение с Pi/OpenCode/Kilo сохраняет [историческую выборку](AGENT_EFFICIENCY_20261019.md): по семь запусков, завершились 5/5/1, медианы завершившихся 210/262.1/146 секунд. Условия и задачи различались; одинаковый benchmark здесь не проводился, рейтинга скорости или качества по этим числам нет. Успешные узкие проверки [LMS](AGENT_EFFICIENCY_20261019_LMS.md), [beamformer](AGENT_EFFICIENCY_20261019_BEAM.md) и ограничения [ISTFT](AGENT_EFFICIENCY_20261019_ISTFT.md) поддерживают текущую схему делегирования: конечный проверяемый расчёт для Luna, архитектура и приёмка для основного агента.
