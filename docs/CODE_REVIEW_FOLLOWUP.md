## Средняя серьёзность

   - `build/questa_matlab_msk/results.json` проверяется только по полю `status`.
   - `compatible/results.json` и `reference.json` не содержат `source_hashes`.
   - Сейчас `verify()` на `build/questa_matlab_msk/results.json` выдаёт STALE (после прогона изменился `tools/check_visual_browser.py`), но `docs/matlab_reference_results.json` подаёт этот результат как действующий.
2. **`tools/report_typed_results.py:21` принимает незавершённые прогоны контрактов.**
   - Для `build/contracts/{all,matlab}_results.json` вызывается только `verify()`, статус не проверяется.
   - Запись `{'status':'RUNNING', **begin()}`, оставшаяся после упавшего прогона при неизменённых исходниках, проходит эту проверку.
   - `build/typed/originals/matlab_results.json` не проверяется вовсе.
   - У `originals/python_results.json` проверяется только статус, а его хэши уже устарели.
3. **Защита от `python -O` есть только в `run_tests`, `run_research` и `check_contracts`.** В остальных местах проверки сделаны через `assert` и под `-O`/`PYTHONOPTIMIZE` отключаются:
   - `check_matlab_msk.py:35,38` — под `-O` пишется `reference.json` со статусом PASS;
   - `report_typed_results.py:19-20`;
   - `report_matlab_originals.py`, около 10 проверок;
   - `visual_report.py:400,413,418`;
   - `typed_visual_report.py:97-105`;
   - `check_visual_browser.py:76,112` и `check_typed_browser.py:12,39` — под `-O` браузерный результат PASS даже при ошибках JS.
4. **Вырожденная MIMO-матрица в трёх языках ведёт себя по-разному.** Пример: `mimo`, p=[2,0], H=[1,1,1,1].
   - Python выбрасывает `LinAlgError` (проверено).

   - Контракт проверяет только `λ≥0`.
   - `check_contracts.py:52` засчитывает любой `ValueError` как отказ до вычислений, а `LinAlgError` — его подкласс. В Octave и HDL требуется сообщение «Invalid DSP».

## Отсутствие RTL

На момент исходного ревью синтезируемого RTL не было. Теперь добавлена начальная библиотека арифметики, памяти и синхронизаторов с отдельной проверкой; см. [RTL_CONTRACT.md](RTL_CONTRACT.md). Полные RTL-модемы ещё не реализованы.

- `modems/*/sv/modem.sv` — трёхстрочные обёртки над `common/sv/modem_model.sv`. Там один `always @(posedge clk)` обрабатывает целый кадр за такт через методы класса на `real`.
- В `modem_dsp_pkg.sv` и `research_dsp_pkg.sv` используются `real`, динамические массивы, `$cos`/`$sqrt`/`$fscanf`.
- В исторических моделях отсутствовали синтезируемые `always_ff`, `.v`/`.vhd` и HDL Coder; новая библиотека `rtl/common/` использует `always_ff`.

Поэтому UVM-сверка с точностью 1e-13 доказывает только совпадение поведенческой модели с Python. Фиксированная точка, латентность, потоковая обработка и сброс состояния не проверены. План создания RTL для всех моделей: [RTL_TODO.md](RTL_TODO.md).
