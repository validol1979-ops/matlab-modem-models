# Luna: границы обновления RLS

Следуя просьбе пользователя учитывать уровень агента, Codex 6 Luna (`gpt-6-luna`, `luna_rls_updates`) получил только конечный целочисленный расчёт: 16 углов комплексных произведений g/e и g/u, восемь углов (P−t)·INVL, сумму с весом после округления и u·R. Архитектура, ограничения переменного сдвига, RTL и приёмка остались у основного агента.

Агент правильно получил общие минимальные ширины 59 для g·conj(e), 44 для суммы с весом, 89 для g·conj(u), 79 для (P−t)·INVL и 71 для u·R при нормированном reciprocal. Привёл точные интервалы и свидетели экстремумов, проверил добавки 2^14/2^29. Основной агент независимо перепроверил формулы и сохранил 128-битное переменное округление gain; агент не получал задачу менять этот алгоритм.

По отчёту агента выполнены два инструментальных вызова: чтение `rtl/common/rls_filter.sv` и вычислительный перебор. Файлы не менял, тесты и синтез не запускал. Достоверные длительность, токены и стоимость отдельного запуска не измерены. Ошибочных арифметических выводов в заданной области не обнаружено; оценка не распространяется на самостоятельную интеграцию.

[Историческая выборка Pi/OpenCode/Kilo](AGENT_EFFICIENCY_20261019.md): по семь запусков, завершились 5/5/1, медианы завершившихся 210/262.1/146 секунд. Задачи и ограничения различались; одинаковый benchmark здесь не проводился и рейтинга по этим цифрам нет. Вместе с предыдущими узкими задачами [LMS](AGENT_EFFICIENCY_20261019_LMS.md), [beamformer](AGENT_EFFICIENCY_20261019_BEAM.md), [Alamouti](AGENT_EFFICIENCY_20261019_ALAMOUTI.md), [сумм RLS](AGENT_EFFICIENCY_20261019_RLS.md) и ограничениями [ISTFT](AGENT_EFFICIENCY_20261019_ISTFT.md) результат поддерживает текущую схему: проверяемая арифметика для Luna, интеграция и приёмка для основного агента.
