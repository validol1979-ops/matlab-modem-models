# Нормировка и обратная подстановка MMSE N×N

`rtl/common/mmse_n.sv` использует отдельные разрядности нормировки, числителя множителя, произведения и аккумулятора обратной подстановки. Общий делитель, `div_num` и `quot_re` сохраняют 112 бит и прежнее число тактов; H18/G40/A34/m48/B72/X72/W64, дробная точность и интерфейс сохранены. Сам аккумулятор подстановки сужен.

| Параметр | Выбранная ширина | Прежняя |
| --- | ---: | ---: |
| `NORM_WIDTH` | 70 | 138 |
| `WEIGHT_WIDTH` | 87 | 138 |
| `MULT_NUM_WIDTH` | 65 | 112 |
| `BACK_PRODUCT_WIDTH` | 107 | 112 |
| `BACK_ACC_WIDTH` | `106+$clog2(N)` | 112 |

Параметры от выбранного минимума до прежнего значения допустимы; меньшие и большие отклоняются `[PARAMETER]`. Для N=2…8 аккумулятор имеет соответственно **107/108/108/109/109/109/109** бит. Перед сужением произведения до ширины аккумулятора проверяются все биты через `fits`; по приведённым границам эта проверка всегда проходит для допустимых кодов, включая смешанные старые/новые ширины.

## Контракт и точные границы

Границы относятся ко всем независимым кодам хранимых операндов. Корреляция матриц, положительная определённость и более узкие наблюдаемые значения не используются. Произвольные направленные состояния не объявляются достижимыми из H или reset.

`dmax` выбирается только из положительных signed40 диагоналей. Поэтому `1≤dmax≤2^39−1`, а `e=bit_length(dmax)−31` лежит в −30…8. Округление при положительном сдвиге — `(x+2^(s−1))>>s`, при нулевом — тождество, при отрицательном — точный левый сдвиг.

- Нормировка G40: результат лежит в **[−2^69, 2^69−2^30]**. Обе границы достигаются при e=−30 на крайних кодах G. Для правого сдвига максимальная сумма до округления равна `2^39+127`, что также помещается в 70 бит.
- Вес X72 при сдвиге e+15∈[−15,23]: **[−2^86, 2^86−2^15]**. Правый rounding add не превосходит `2^71+2^22−1`, что помещается в 87 бит. Проверка signed64 выполняется по полному результату до записи W.
- Действительный числитель A34<<30: **[−2^63, 2^63−2^30]**. Сопряжённая мнимая часть: **[−2^63+2^30, +2^63]**. Именно положительный конец требует общих 65 бит. Затем выполняется явное знаковое расширение до 112 бит делителя.

Для произведения A34·X72 обозначим `a=2^33`, `b=2^71`, `P=2ab=2^105`. Перебор четырёх независимых крайних компонент даёт:

| Компонента произведения | Минимум | Максимум |
| --- | ---: | ---: |
| real | −P+a | P−a |
| imag | −P+2a | P |

Мнимая компонента равна **+2^105**, если обе компоненты A равны −2^33 и обе компоненты X равны −2^71. Signed106 это число не представляет, поэтому общий продукт требует 107 бит.

Начальный аккумулятор B72<<30 лежит в `[−2^101, 2^101−2^30]`. После t вычитаний, для любого префикса `0≤t≤N−1`:

| Компонента аккумулятора | Минимум | Максимум |
| --- | ---: | ---: |
| real | −2^101−t(P−a) | 2^101−2^30+t(P−a) |
| imag | −2^101−tP | 2^101−2^30+t(P−2a) |

Границы достижимы в контракте независимых кодов: повторяется соответствующий угловой продукт и выбирается крайний начальный B. Самый отрицательный случай — `−2^101−(N−1)·2^105`; он исключает уменьшение общей ширины аккумулятора ещё на один бит для каждого N=2…8.

FSM начинает последнюю строку с `cc=N`; при переходе к предыдущей строке задаёт `cc=new_ck+1`, при следующем столбце — `ck+1`. `C_BACK` вычитает только при `cc<N`; заключительный проход с `cc=N` лишь переводит в `C_SOLVE`. Значит, t≤N−1 и все промежуточные суммы покрыты. Проверяются все три места инициализации аккумулятора и знаковое расширение в оба типа запуска делителя.

## Проверка

`common/python/mmse_norm_back_widths.py` содержит интервалы и независимую целочисленную трассу Gram/нормировки/исключения/подстановки/весов. Она не читает промежуточные состояния fixed-модели; итоговые веса сравниваются с неизменённой `mmse_n_fixed.py`. Шесть новых Python-тестов проверяют крайние коды, rounding add, отрицательные ничьи, каждый префикс, все N и отказ валидатора при пропусках, дубликатах и подменах свидетельств.

Монитор `mmse_n_norm_back_check.svh` пересчитывает фактические операнды в signed192 до `fits`/усечения, проверяет следующий аккумулятор и числитель делителя. Десять банков count/min/max (две компоненты нормировки, числителя, произведения, аккумулятора и веса) сравниваются с независимой Python-трассой. После полных повторных конфигураций при сбросах счётчики должны удваиваться; сброс внутри конфигурации не добавляет завершённых операций.

Направленный стенд перебирает 16 углов компонент A/X, крайние G/B и каждый допустимый e. Он проверяет полные результаты и signed34/signed64-защиты, а затем выполняет настоящий `C_BACK` для всех N−1 вычитаний. Источники заданы статическими force; начальные управляющие регистры и аккумулятор кратко задаются через force/release, во время цикла аккумулятор записывает сам DUT. Это самостоятельный тест арифметики по хранимым кодам, не входная конфигурация H.

Запуск: `python3 tools/mmse_norm_back_sweep.py --verify-rtl --jobs 8`. Отчёт без `--verify-rtl` содержит только модельную часть и не выдаётся за RTL-приёмку. Синтез остаётся на согласованной паузе; физические ресурсы и частота не измерены.
