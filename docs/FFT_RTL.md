## Ядро `fft_r2sdf`

| Параметр или порт | Значение |
| --- | --- |
| `LOG2N` | 2…10, N = 2^LOG2N; размер задаётся при синтезе |
| `TWIDDLE_FILE` | `rtl/common/mem/fft_twiddle_<N>.mem` |
| Вход | 18 бит; `s_valid/s_ready/s_last`; кадр — ровно N отсчётов; `s_inverse` защёлкивается на первом отсчёте кадра |
| Выход | 20 бит, естественный порядок; `m_valid/m_ready/m_last`, `m_inverse` |
| `error` | залипающий флаг: `s_last` не на N-м отсчёте (границы кадров задаёт счётчик) |

**Арифметика** (бит в бит с `fft_fixed`):
- Твиддлы W = cos − j·sin в Q16, 18 бит. cos 0 = 65536 помещается в 18 бит со знаком.
- Округление половины вверх: (v + 2^(s−1)) >> s.
- **Прямое** (`s_inverse = 0`): FFT(x)/N. Каждый каскад делит пополам: сумма — round((a+b)·2¹⁶, 17), разность — round((a−b)·W, 17). Переполнение невозможно, потому что |X/N| ≤ max|x|; вход до ±2¹⁷ даёт на выходе не больше 185 364.
- **Обратное** (`s_inverse = 1`): Σₖ yₖ·e^{+j2πkt/N}, без 1/N, то есть точное обращение прямого. Считается как conj(без деления(conj(y))): каскады округляют на 16 бит и насыщают до ±(2¹⁹−1). Результат точен, пока он и частичные суммы помещаются в 20 бит; например, вход спектрального масштаба x/N.
- Прямое и обратное возвращают сигнал с ошибкой в несколько единиц младшего разряда на каскад, см. `test_round_trip`.

**Структура:**
- Каскад s (D = N/2^(s+1)) держит линию задержки на D комплексных слов (21 + 21 бит) плюс бит направления.
- Позиции c < D: вход уходит в линию задержки, на выход идёт сохранённая разность бабочки j = c с твиддлом k = j·2^s.
- Позиции c ≥ D: на выход идёт сумма a+b, в линию уходит разность a−b.
- Выход каскада умножается на твиддл из ROM, 4 умножителя. P = 4 регистра на каскад: операнд и чтение ROM, произведения, округлённая и сдвинутая сумма, насыщение. Последний каскад (k = 0) обходится без умножителей.
- Линия задержки `fft_delay`: регистры при глубине до 16, `sync_ram` с опережающим чтением при большей.
- Бит направления идёт с каждым отсчётом, поэтому соседние кадры могут быть разного направления.

**Продвижение конвейера:**
- Цепочка двигается, только когда принят отсчёт или вставлен «пузырь».
- Кадры подряд идут 1 отсчёт/такт без пузырей.
- Если кадр кончился, а следующего отсчёта нет, ядро сливает конвейер: `s_ready` = 0, L = N−1 + 4·LOG2N пузырей. Следующий кадр стартует на пустой цепочке.
- Пауза внутри кадра просто останавливает цепочку.

**Переупорядочивание:** два банка по N слов в одном `sync_ram`. Выход i пишется по адресу bitrev(i); полный банк читается по порядку в выходную FIFO на 4 слова с обратным давлением `m_ready`. Цепочка ждёт, только если следующий банк ещё не прочитан. Задержка от первого отсчёта кадра до первого выхода — около L + N + 3 тактов.

## OFDM (`ofdm_awgn`)

| Блок | Тракт |
| --- | --- |
| `ofdm_tx` | Q15-символы (N на кадр) → y = round(s·K, SHIFT_TX) = s/√N → обратное FFT без деления = ifft(s)·√N → насыщение до 18 бит → буфер префикса (два банка) → N+CP отсчётов: wave[N−CP…N−1], wave[0…N−1] |
| `ofdm_rx` | N+CP отсчётов → первые CP отбрасываются → прямое FFT (X/N) → ×√N = K·2^−SHIFT_RX, округление, насыщение до 18 бит → N символов |

Константы: K = 46341 (√2·2¹⁵) при нечётном LOG2N и 32768 при чётном; SHIFT_TX = 15 + ⌈LOG2N/2⌉; SHIFT_RX = 15 − ⌊LOG2N/2⌋.

Модель совпадает с `research_core.run('ofdm_tx'/'ofdm_rx')`:
- при N ≤ 64 — до 2·10⁻³;
- при N = 1024 — до 6·10⁻³, около −48 дБ от символа единичной мощности; шум округления растёт с N.

Решения по всем созвездиям 2/4/16/64 при шуме 0.003 верные.

## STFT и ISTFT (`audio/stft`)

Блоки `rtl/common/stft_analysis.sv` и `rtl/common/stft_synthesis.sv`; эталон — `common/python/stft_fixed.py`, тесты — `tests/test_stft_fixed.py`, прогон — `python3 tools/run_stft.py --suite all` (векторы `tools/stft_cases.py`, тестбенч `rtl/tb/stft_tb.sv`). Таблицы окна `stft_window_<N>.mem` и обратных норм `stft_recip_<N>_<HOP>.mem` генерирует `tools/fft_tables.py`.

**Допустимые размеры:** N = 4…256, HOP = N/R, R ∈ {1, 2, 4}.
- Окно sqrt-Hann с ненулевыми краями (как в модели).
- Нормированный overlap-add делит на Σw², а на первом отсчёте при N = 64 это 6·10⁻⁴. Поэтому края требуют запаса точности.
- N = 1024 отвергается: окно на краю ≈ 0.0015, краевые отсчёты теряют смысл.

**Параметризация ядра.** Для запаса ядру `fft_r2sdf` добавлены параметры `IN_WIDTH` и `WIDTH`:
- по умолчанию 18/20 — прежнее поведение, бит в бит;
- допустимо IN_WIDTH + 1 ≤ WIDTH ≤ 24, по-прежнему одно умножение 25×18 на произведение;
- `run_fft.py` проверяет и широкую конфигурацию 22/24 при N = 64 и 256.

**Анализ** (одна транзакция — сигнал из L отсчётов Q15 с `s_last`):
- Кадры f = 0…F−1, F = 1 + (L−N)/HOP; хвост после последнего полного кадра принимается и отбрасывается; L < N даёт `error`.
- z = round(x·W, 13): W — окно Q17, z — Q19 в 22 битах (4 защитных бита).
- Прямое FFT 22→24 бит, выход X/N в Q19, 24 бита, `m_last` на последнем бине транзакции.
- Кольцевой буфер на 2N отсчётов. Кадр читается, когда пришли его отсчёты и либо отсчёты следующего кадра, либо `s_last`, поэтому при выдаче уже известно, последний ли он; флаг доходит до выхода FFT через FIFO по кадрам.
- На кадр уходит N тактов, так что вход идёт со скоростью до 1/R отсчёта за такт.

**Синтез** (транзакция — F кадров по N бинов, `s_last` на последнем):
- Спектр насыщается до ±(2²²−1); для выхода анализа это насыщение никогда не срабатывает.
- Обратное FFT без деления (23→24 бит) даёт кадр u ≈ x·w в Q19.
- acc[t] += u·W точно, 44 бита, в кольце на N слов: чтение, изменение и запись за три регистра.
- После кадра f выдаются отсчёты t = f·HOP…f·HOP+HOP−1, после последнего кадра — все N оставшихся. Каждый умножается на RECIP[t mod HOP][маска], округляется на 17 + 4 + F бит и насыщается до 18 бит. Бит m маски означает, что существует кадр ⌊t/HOP⌋ − m; так края (начало и хвост) нормируются ровно как в модели.
- Дробность таблицы F = 24 − 2·LOG2N: максимум 1/Σw² = 1/sin²(π/2N), формула проверена для всех N.
- Накопление и выдача делят порты RAM, поэтому на кадр уходит N + HOP + 8 тактов.
- После `s_last` вход ждёт, пока последний кадр транзакции не будет выдан.

**Точность** (`test_stft_fixed`, комплексный гауссов сигнал):

| N, HOP | Анализ: \|X/N − эталон\| | Восстановление: максимум | внутри сигнала | СКО |
| --- | --- | --- | --- | --- |
| 64, 16 | < 2 LSB Q15 | 0.0037 (край) | 4.7·10⁻⁵ | 2.3·10⁻⁴ |
| 64, 32 | < 2 LSB Q15 | 0.0039 | 4.8·10⁻⁵ | 2.9·10⁻⁴ |
| 32, 32 (R = 1) | < 2 LSB Q15 | 0.0010 | — | 1.7·10⁻⁴ |
| 256, 64 | < 2 LSB Q15 | 0.057 (первые отсчёты) | 5.9·10⁻⁵ | 1.9·10⁻³ |

Без защитных бит на краях было 0.05–0.06 даже при N = 64.

**Проверка Questa:**
- (N, HOP) = (4, 1), (32, 8), (32, 32), (64, 16), (64, 32), (256, 64);
- 4 транзакции разной длины, при N = 256 — 2; есть транзакция ровно из N отсчётов и хвосты, не заполняющие кадр;
- потоковый режим и режим со случайными паузами на входе и выходе, обе полярности сброса, отрицательный контроль;
- анализ сверяется с `stft_fixed.analyze`, синтез — с `stft_fixed.synthesize` на тех же спектрах, бит в бит.

## Полифазный банк (`channelizers/pfb_wola`)

Операции `pfb` и `wola` в модели — одно и то же преобразование. Блок — `rtl/common/pfb_analysis.sv`; эталон — `common/python/pfb_fixed.py`, тесты — `tests/test_pfb_fixed.py`, прогон — `python3 tools/run_pfb.py --suite all` (векторы `tools/pfb_cases.py`, тестбенч `rtl/tb/pfb_tb.sv`).

**Параметры:**
- при синтезе: M = 2^LOG2M (4…64), число полос LANES = 2^LOG2LANES (делитель M), максимум отводов TMAX = 2^LOG2TMAX;
- в рабочем режиме, через порт конфигурации: T отводов в Q17 (`cfg_tap`, `cfg_last` на последнем) и децимация D от 1 до M (`cfg_decimation`, защёлкивается с `cfg_last`).

Конфигурация принимается только между транзакциями. Ошибки (больше TMAX отводов, D вне диапазона) поднимают `error`.

**Арифметика** (бит в бит с `pfb_fixed`):
- Для каждого момента end = 0, D, 2D, … < L: acc[n] = Σ H[j]·x[end−j] точно, по j ≤ min(end, T−1) и j mod M = n.
- p[n] = sat22(round(acc[n], 13)) — Q19, 4 защитных бита.
- Поворот e^{2πj·k·end/M} заменён циклическим сдвигом фаз q[m] = p[(m+end) mod M] (теорема о сдвиге), поэтому дополнительных умножений нет.
- Y = прямое FFT 22→24 бит = fft(q)/M в Q19.
- С вещественной моделью `research_core` при случае из `model.json` (M = 4, 33 отвода firwin, два тона) расхождение 1.4·10⁻⁵ при амплитуде 1. Основной вклад — квантование отводов.

**Структура:**
- Шаг c обрабатывает отводы j = c·LANES + l в LANES полосах (2 DSP на полосу).
- Отводы лежат в LANES банках: банк l, адрес c.
- История сигнала — кольцо на RING = 4·max(TMAX, M) отсчётов в LANES банках, отсчёт t в банке t mod LANES. Полоса l читает банк (end − l) mod LANES, так что за шаг каждый банк читается один раз.
- Момент end занимает ⌈T/LANES⌉ шагов и 4 такта конвейера. Следующий момент накапливается, пока фазы предыдущего идут в FFT (M тактов). В итоге около max(⌈T/LANES⌉ + 5, M) тактов на момент, то есть вход до D/max(…) отсчёта за такт.
- Момент запускается, когда пришли его отсчёт и отсчёты следующего момента (или `s_last`); признак последнего момента транзакции доходит до выхода через FIFO.

**Проверка Questa** — (M, LANES, TMAX, D, T):

| M | LANES | TMAX | D | T |
| --- | --- | --- | --- | --- |
| 4 | 4 | 64 | 4 | 33 |
| 4 | 4 | 64 | 3 | 33 |
| 4 | 1 | 64 | 3 | 33 |
| 8 | 2 | 64 | 5 | 40 |
| 16 | 16 | 128 | 16 | 64 |
| 64 | 8 | 256 | 32 | 129 |
| 4 | 2 | 4 | 1 | 3 |

Для каждой строки:
- обе полярности сброса, потоковый режим и режим с паузами на входе и выходе;
- первая транзакция в случаях M = 4, T = 33 — сигнал и отводы из `model.json`, затем транзакции случайной длины;
- отрицательный контроль.

Всё совпадает бит в бит.

Первая сборка остановилась на Quartus 10030 для `memory.waddr_a[0]`: у ROM твиддлов при M = 4 однобитный адрес. Разрешающее правило в `rtl/warnings.json` дополнено необязательным индексом; повторная сборка ещё не выполнялась.

## harger: операция `dft`

Операция `dft` — это само ядро: прямое даёт X/N, обратное — Σ без 1/N. Случаи модели в масштабе Q15:
- `dft_single_bin`: тон e^{2πj·7t/64} даёт в прямом бин 7 с амплитудой тона, то есть X/N (в тесте амплитуда 100 000 и точность ±8 единиц);
- `inverse_dft`: спектр с единственным бином 1.0 (32 768) даёт в обратном тот же тон (точность ±4 единицы).

Обе проверки — в `tests/test_fft_fixed.py::test_tone_and_impulse`. Операция `fir` из `harger` — блок `fir_runtime`, см. [DSP_RTL.md](DSP_RTL.md).

## Проверка

`run_fft.py --suite all`: lint при LOG2N = 2, 3, 5, 6, 10; Questa при N = 4, 32, 64, 1024 и обеих полярностях сброса.

| Сценарий | Что проверяет |
| --- | --- |
| stream | 24 кадра подряд (6 при N = 1024). Каждый отсчёт должен приниматься с первого такта, иначе `[THROUGHPUT]` |
| gaps | короткие паузы внутри кадров и длинные (N+20…2N) перед кадрами: сливы конвейера |
| backpressure | то же плюс случайные паузы на входе и случайный `m_ready` |
| negative / bad_last | искажённый ожидаемый выход должен дать `[NUMERIC]`; ранний `s_last` должен поднять `error` |

Кадры векторов:
- случайные во всю шкалу и постоянные угловые (±2¹⁷);
- одиночный импульс, тон, малые значения;
- случайные спектрального масштаба.

Направление случайно и меняется от кадра к кадру. Обратное от полномасштабных кадров уходит в насыщение (47 насыщенных выходов при N = 64), и это тоже сверяется бит в бит.

`run_ofdm.py --suite all`: (N, CP) = (32, 8), (32, 0), (64, 16), (4, 1), (1024, 64), потоковый режим и режим с паузами на входе и выходе, обе полярности сброса, отрицательный контроль. Передатчик сверяется с `ofdm_fixed.transmit`. Приёмник получает зашумлённый вещественный сигнал `research_core` в Q15 и сверяется с `ofdm_fixed.receive`; ошибок по символам 0.

Что понадобилось:
- В первой версии сумма произведений, округление и насыщение шли в одном такте, и Cyclone V дал +0.54 нс при требуемом запасе 1 нс. Теперь это два регистра (P = 4), а насыщение — проверка старших бит, без сравнения 41-битных чисел.
- Синтез копировал из `rtl/common/mem` только `test_rom.mem`. Vivado предупредил, что не открыл файл твиддлов, и прогон был отклонён. Теперь `run_rtl_synth.py` копирует все `.mem` каталога.
- В `fft_delay` у адреса RAM-линии синхронный сброс: начальное значение регистра Verilator отвергает (PROCASSINIT), без него в Questa адрес был бы X.
- Quartus Standard требует `generate … endgenerate` вокруг generate-`if` (ошибка 10170).
- Vivado выбрасывает разряды, которые не влияют на результат, и предупреждает об этом (8-3936, 8-3332). Произведения объявлены ровно нужной ширины: x·W в анализе — 35 бит, потому что окно < 2¹⁷. В синтезе регистр хранит произведение acc·RECIP только начиная с бита SHIFT−1, а округление — (v+1)>>>1.
- Синтез: перед умножителем 44×25 стоит регистр операндов. Без него путь «выход ROM → умножитель» давал в Artix-7 −1.84 нс.
