# Luna: границы энергии beamformer

Пользователь просил учитывать уровень агента при назначении работы. Codex 6 Luna (`gpt-6-luna`, `luna_beam_energy`) получил ограниченную read-only задачу: вычислить unsigned ширины суммы квадратов комплексных signed18 коэффициентов для M=1/2/4/8/16/32/64 и проверить размеры входа/выходного сдвига в двух заданных RTL-файлах. Изменения, тестовые мониторы и приёмку выполнил основной агент.

За один инструментальный вызов Luna прочитал `beamform.sv` и `norm_reciprocal.sv`, правильно получил ширины 36…42 и указал, что прежние 40 бит перестают покрывать полный диапазон при M=32. Для рассматриваемых границ подтвердил достаточность семибитного z/shift и ширины числителя делителя при корректном параметре WIDTH. Агент явно отметил, что не проверял реализацию делителя, симуляцию и синтез. Ошибочных выводов в заданной области не обнаружено. Основной агент независимо воспроизвёл оба вида переполнения в старом RTL и проверил исправление симуляцией.

Достоверные длительность отдельного агентского запуска, стоимость и токены не измерены. Одного успешного расчёта недостаточно для оценки самостоятельной интеграции. Результат подтверждает пользу Luna для конечных проверяемых арифметических задач; архитектура и интеграция остаются у основного агента.

Сравнение с Pi/OpenCode/Kilo сохраняет [историческую выборку](AGENT_EFFICIENCY_20261019.md): по семь запусков, завершились 5/5/1, медианы завершившихся 210/262.1/146 секунд. Задачи и лимиты отличались; одинаковый benchmark на этом этапе не запускался. Честного рейтинга скорости или качества относительно текущей задачи Luna эти данные не дают.
