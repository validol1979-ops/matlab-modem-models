# Начальная библиотека RTL

Начальная библиотека содержит переносимые арифметические блоки, память, синхронизаторы и средства проверки. Добавлен код полного BPSK TX/RX и битоточный эталон; интерфейсы и статус физической приёмки описаны в [BPSK_RTL.md](BPSK_RTL.md). Вещественные модели в `common/sv/` остаются отдельными эталонами.

## Фиксированная точка

`common/python/fixed_point.py` задаёт знаковый формат `QFormat(width, frac)`: `width` включает знак, значение равно целому коду / 2^frac. Начальный формат отсчёта — 18 бит, 15 дробных, диапазон −4…4−2⁻¹⁵. Это исходный формат арифметики, а не окончательный выбор для всех модемов.

Округление — к ближайшему, точная середина к чётному; затем насыщение к границам. Флаги переполнения относятся к округлённому результату до насыщения: bit 0 — I, bit 1 — Q. Python считает целыми неограниченной разрядности; RTL сохраняет полный результат произведения/суммы до единственного округления на выходе. Статистика Python отдельно считает округления и оба направления насыщения.

## Блоки и интерфейс

| Блок | По умолчанию | Латентность без остановок |
| --- | --- | ---: |
| `fxp_complex_mul` | (18/15) × (18/15) → 18/15; четыре произведения, 37-битная сумма | 4 такта |
| `fxp_complex_add` | 18/15 + 18/15 → 18/15 | 2 такта |
| `fxp_stream_resize` | две компоненты 37/30 → 18/15 | 1 такт |
| `fxp_round_sat` | параметризуемое округление/насыщение, включая увеличение frac | комбинационно |
| `sync_ram` | 1024 × 18, простой двухпортовый доступ | регистровое чтение, 1 такт |
| `sync_rom` | 256 × 18, `$readmemb` | регистровое чтение, 1 такт |
| `bit_sync` | одиночный управляющий бит | 2 фронта |
| `reset_sync` | синхронная обработка внешнего сброса | снятие после 2 фронтов |
| `fxp_divide_seq` | знаковое NUM_WIDTH / беззнаковое DEN_WIDTH (по умолчанию 64/32), точное округление к ближайшему чётному | NUM_WIDTH+2 такта на деление |
| `fxp_mrc2` | две ветви 18/15, усиления 18/15, дисперсии 1…65535, веса 18/14 → 18/15 | 6 тактов (5 ступеней и FIFO) |

Арифметика использует плоские `s_*`/`m_*` порты, valid/ready и last. Передача происходит на фронте при valid && ready. При остановке выхода весь конвейер удерживается; выходные данные, overflow и last стабильны. Без остановок принимается и выдаётся один комплексный отсчёт за такт. Last проходит вместе с отсчётом, арифметического смысла не имеет. Латентность измеряется между фронтами принятия входа и потребления выхода.

Сброс синхронный, `RESET_ACTIVE` выбирает полярность. Сбрасываются valid и управляющие регистры; данные конвейера не сбрасываются и допустимы только при valid. Сброс отменяет все ожидающие отсчёты. Пока сброс активен, ready и valid арифметических блоков равны нулю.

`fxp_divide_seq` — запуск импульсом `start` при `busy=0`, результат вместе с импульсом `done`; нулевой знаменатель — ошибка вызывающего блока. `fxp_mrc2` — объединение двух ветвей с известными усилениями (эталон `common/python/mrc_fixed.py`): после `cfg_valid` за ~310 тактов один общий умножитель и делитель считают веса `w_a = conj(g_a)·v_b/D`, `w_b = conj(g_b)·v_a/D`, `D = |g_a|²v_b + |g_b|²v_a`. Нулевая дисперсия, `D = 0` или вес вне Q4.14 (|w| ≥ 8) дают `error`, блок остаётся ненастроенным. Конфигурация принимается только без отсчётов в тракте. Тракт не останавливается: вход получает кредиты по числу свободных мест в выходном FIFO на 8 слов, поэтому `m_ready` не управляет разрешением DSP. Флаг `saturated` залипает до следующей конфигурации.

RAM не инициализируется и не сбрасывается; одновременное чтение/запись одного адреса возвращает прежнее значение. При rd_en=0 выход удерживается. ROM содержит только тестовую таблицу; коэффициенты модемов будут отдельными артефактами. `bit_sync` предназначен для одного управляющего бита, не для шины данных. `reset_sync` требует внешнего сброса длительностью не менее трёх тактов; ядро видит его на следующем фронте. Проверка симуляцией не доказывает устойчивость к метастабильности; для интеграции доменов ещё нужны ограничения CDC и FIFO.

## Проверки и команды

Зависимости Python: `requirements-rtl.txt`. Запуск из корня проекта:

```bash
python3 tools/run_rtl.py --suite all
python3 tools/run_rtl_synth.py
python3 tools/rtl_precision.py
python3 tools/run_tests.py --suite rtl
```

`--suite rtl` объединяет Python/Verilator/Questa и синтез обоих вендоров. Обычная `--suite all` сохраняет отдельную регрессию вещественных моделей. `run_rtl.py --block complex_mul` ограничивает арифметические тесты, `run_rtl_synth.py --block ram --vendor altera` — физический синтез.

UVM сравнивает целочисленные выходы, overflow и last с Python, проверяет задержку и пропускную способность, случайные паузы, длительные остановки, сброс посреди потока, повторный поток без сброса и обе полярности сброса. SVA контролирует удержание входа/выхода и отсутствие неизвестных значений при valid. Covergroup учитывает overflow и last. Для памяти, преобразования форматов и синхронизаторов используется отдельный самопроверяющий SV-тест. Каждый тест имеет негативный контроль с намеренной порчей ожидаемого значения. Полное покрытие параметров и модемных режимов остаётся дальнейшей задачей.

Questa запускается без вендорных библиотек, с UVM 1.2 и системным GCC. Дополнительная Questa FSE проверяется явным `--questa-bin ~/altera/25.1std/questa_fse/bin`; текущая установка отказывает в выдаче лицензии. Это не PASS и не заменяется пропуском теста.

## Синтез

Общий YAML `rtl/constraints/common.yaml` задаёт 100 МГц, uncertainty 0.2 нс, входной/выходной бюджет 1 нс, ёмкость выхода 5 пФ (XDC set_load, Quartus BOARD_MODEL_FAR_C) и пороги запаса. Генерируются XDC/SDC; нет широких false-path исключений. Vivado и Quartus выполняют размещение и трассировку Artix-7 xc7a35tcpg236-1 и Cyclone V 5CSEMA5F31C6. Принятие требует положительных setup/hold; для Cyclone V setup не меньше 1 нс. Неизвестные и критические предупреждения запрещены; обоснованные исключения перечислены в `rtl/warnings.json`. Для Quartus 10030 разрешены только три неиспользуемых входа записи внутренней ROM (`memory.data_a`, `memory.waddr_a`, `memory.we_a`), которые инструмент привязывает к нулю; другие недрайвленные сигналы остаются ошибкой.

`rtl/rtl_synth_top.sv` — регистровая тестовая обвязка с генерируемыми операндами и выходными регистрами. Выходы смешиваются с сигналами обвязки, чтобы все выводы оставались динамическими даже у маленьких DUT; интерфейс обвязки не является интерфейсом модема. Ресурсы и тайминг включают её. IO назначены детерминированно на доступные выводы корпуса, с уровнями LVCMOS18 для Artix-7 и 2.5 В для Cyclone V, быстрым фронтом и нагрузкой 5 пФ; это стенд для инструментов, не назначение выводов готовой платы. Оценка Fmax по запасу при 100 МГц не заменяет отдельную сборку на более высокой частоте. Quartus получает идентичные копии исходников в ASCII-пути `/tmp`, поскольку его Tcl не открывает путь проекта с кириллицей.

Артефакты: `build/rtl/rtl_results.json`, `build/rtl/<block>/reset_<polarity>/`, `build/rtl/synth/results.json`, отчёты по блокам, UVM-логи и векторы. JSON PASS появляется только после завершения и включает хэши исходников и артефактов. Изменение исходников требует новой проверки.

`rtl_precision.py` исследует только квантование входа существующих 24 приёмников на чистом и искажённом сигнале при 12/14/16/18 битах. Фильтры и петли остаются вещественными; этот отчёт не доказывает SER полного fixed-point приёмника. Для BPSK отдельный `tools/bpsk_precision.py` измеряет полный fixed-point SER и квантование внутренних узлов.

## Исторический результат начальной инфраструктуры, 2026-10-01

Единая `--suite rtl` завершилась PASS: 14 Python-тестов инфраструктуры, восемь lint-верхних уровней, шесть UVM-запусков для трёх блоков и двух полярностей сброса (6 874 побитовых сравнения), поддерживающий SV-тест и семь негативных контролей. Общая Python-регрессия прошла 205 тестов. Все 14 сборок завершили размещение/трассировку на 100 МГц. JSON, исходники и артефакты были проверены через `require_pass` в момент завершения начального этапа.
