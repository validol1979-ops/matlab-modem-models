# Конечный перебор захвата потоковой петли Costas

## Область эксперимента

Модель `sync_fixed.costas_pipelined` (задержка 10 продвижений, коэффициенты `0.08, 0.001`) обрабатывает плотный поток из 3072 отсчётов QPSK. Каждый отсчёт — новый независимый идеальный QPSK-символ единичной мощности; формирующего фильтра и тактовой синхронизации нет. Начальная фаза −0.6, 0, +0.6 радиан; постоянное отклонение частоты −0.012, 0, +0.012 радиан на отсчёт; шум отсутствует либо комплексный AWGN при SNR 24, 12, 6 дБ. SNR — отношение мощности сигнала к суммарной мощности комплексного шума. Два seed на каждую комбинацию: всего 72 случая. Вход переводится в Q15 и ограничивается диапазоном signed18; в этих прогонах ограниченных компонент нет.

Известная истинная фаза сравнивается с фазой, использованной для вращения, по модулю π/2. Для каждого полного окна 128 отсчётов критерий качества — среднее абсолютной ошибки < 0.12 радиан и 90-й процентиль < 0.30 радиан. Захватом называются два последовательных качественных окна. Показатель «слежение в конце» требует двух последних качественных окон. Число некачественных окон после захвата включает любые его потери, включая окна последующего восстановления.

Для оценки неоднозначности разматывается ошибка относительно истинной фазы, и сравниваются медианные номера квадранта двух последовательных качественных окон, в том числе после некачественных окон. Это **наблюдаемая смена ветви**, а не число отдельных cycle slip: между окнами могут быть несколько переходов, скачки свыше π между отсчётами неоднозначны при размотке, а короткие события сглаживаются. Данные не позволяют утверждать отсутствие кратковременных срывов внутри качественного окна.

## Результат

| SNR | Захват из 18 | Слежение в конце из 18 | Случаи со сменой ветви | Некачественные окна после захвата |
| --- | ---: | ---: | ---: | ---: |
| без шума | 18 | 18 | 0 | 0 |
| 24 дБ | 18 | 18 | 0 | 0 |
| 12 дБ | 18 | 17 | 0 | 10 |
| 6 дБ | 14 | 0 | 2 | 125 |

У контрольной петли с нулевыми коэффициентами, при фазе 0.6 и отклонении 0.012 рад/отсчёт без шума, захвата и слежения в конце нет. Условия и результаты каждой траектории сохранены отдельно в [JSON](rtl_costas_stream_acquisition_20261029_results.json).

Это конечный, короткий перебор с двумя реализациями шума на точку, без оценки доверительных интервалов. Он не устанавливает полной области захвата, частоты ошибок, устойчивости при других коэффициентах, помехах или фильтрации. Модель ранее сверена с RTL на отдельных векторах; этот перебор является только модельным исследованием и не измеряет тактовую частоту или сквозной темп приёмника.

## RTL-подтверждение — PASS (2026-10-29)

Добавлен отдельный раннер [run_costas_stream_acquisition.py](../tools/run_costas_stream_acquisition.py). Он использует исходный `costas_stream_acquisition.signal` с теми же seed, AWGN, округлением и ограничением Q15/signed18. Для всех 72 траекторий и нулевого контроля генерируются ожидаемые слова `sync_fixed.costas_pipelined` через существующий `write_case`. До запуска HDL проверяется точное совпадение всех полей результатов модели с историческим JSON, включая вещественную метрику последнего окна. Состав сетки, длина 3072, окно 128 и задержка 10 проверяются отдельно.

Для каждого `RESET_ACTIVE=1/0` предусмотрен отдельный плотный прогон каждой траектории существующим `costas_stream_tb.sv` в Questa. Тестбенч сверяет `{re, im, phase, last}` и сохраняет принятые выходы через `+OBSERVED`; Python повторно проверяет формат, число и каждое слово этого файла. **Метрики RTL считаются только из фаз файла OBSERVED**, после побитной сверки, и должны целиком совпасть с записью соответствующей траектории в старом JSON. Плотный поток должен дать `run_max=3072`, `gap_max=out_gap_max=0`, `span=3071`. На первой траектории при каждой полярности предусмотрен `+INJECT_MISMATCH`: принимается только численный Fatal нужного scoreboard, отсутствие PASS и **ровно код процесса 13**.

Результат приёмки `build/rtl/costas_stream_acquisition_rtl_20261029/acquisition_results.json` — **PASS**, Questa 2024.1:

Тем самым таблица захвата по SNR выше теперь описывает и RTL `costas_stream.sv`: расхождений RTL/модель нет ни в одном слове. Арифметика модуля, модель `sync_fixed.costas_pipelined` и тестбенч не менялись. Утверждение по-прежнему ограничено конечной сеткой идеального QPSK с плотным входом; полная область захвата, другие коэффициенты и физический тайминг не измерялись, синтез остаётся на согласованной паузе.

Ранний каталог `build/rtl/costas_stream_acquisition_rtl/` (и `_attempt1/2`) — сохранённое свидетельство **FAIL** первого запуска внутри sandbox Codex, где `vsim` получал SIGSYS до компиляции; это отказ среды, не RTL. Он не переписывался. Повторный запуск выполнен вне sandbox в новом каталоге:

```bash
python3 tools/run_costas_stream_acquisition.py --output-dir build/rtl/costas_stream_acquisition_rtl_20261029
```

Раннер сам запускает указанный набор Python-тестов и lint, записывает PASS только после всех 146 положительных прогонов и двух отрицательных контролей и сразу проверяет `require_pass`. При обычном отказе пишет FAIL с доступными хешами и повторно возбуждает исключение. Существующий выходной каталог отвергается до записи. Unit-тесты дополнительно проверяют отбраковку неполной/дублированной сетки, повреждения каждого поля слова, пропущенных/лишних строк, неверных метрик, ложного PASS, неправильного отрицательного контроля и защиту прежнего свидетельства от перезаписи.

## Воспроизведение

```bash
python3 tools/costas_stream_acquisition.py --output <local-tmp>
python3 -m pytest -q tests/test_costas_stream_acquisition.py
```

Программа отказывается перезаписывать существующий файл. Проверки охватывают воспроизводимость генератора, мощность шума, положительный и нулевой контроли, искусственную смену ветви через плохое окно и некорректный ввод. Сохранённые результаты являются отдельным свидетельством и не изменяют прежние отчёты.
