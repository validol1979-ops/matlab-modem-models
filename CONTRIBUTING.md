# Как вносить изменения

1. Создайте ветку от `main` и держите изменение узким: одна модель, один блок RTL или одна проверка.
2. Комментарии в новом коде пишутся по-русски, диагностические сообщения и имена — по-английски; стиль — как в окружающем коде.
3. Изменение RTL сопровождается изменением целочисленной модели в `common/python/*_fixed.py` (если меняется поведение), направленным тестом в `rtl/tb/` и отрицательным контролем, который ломается на старой версии.
4. Перед pull request выполните из корня проекта:

   ```bash
   python3 -m pytest -q tests
   python3 tools/run_tests.py --suite python
   ```

   Для RTL дополнительно — соответствующий раннер (`tools/run_streaming_rtl.py --blocks <имя> --suite all`, `tools/run_bpsk.py --suite all` и т.п.) с Questa и Verilator. В описании PR укажите, какие команды запускались и с каким результатом.
5. Раннеры с `--output`/`--output-dir` отказываются писать в существующий каталог: используйте новый каталог, не перезаписывайте прежние свидетельства.
6. Не добавляйте сторонние модели и исходники без явной лицензии, разрешающей распространение; указывайте их в [THIRD_PARTY.md](THIRD_PARTY.md).
7. README каталогов ведутся вручную: генераторы рабочих пространств их не перезаписывают.

## Структура папки модели

Новые модели в `modems/<имя>/` должны иметь следующую структуру:

| Файл / каталог | Назначение |
| --- | --- |
| `config.json` | Параметры модели и метаданные происхождения |
| `README.md` | Описание на русском, запуск, наблюдения и ограничения |
| `run_demo.m` | Запуск исторической модели из `matlab/`; при её отсутствии — понятная ошибка со ссылкой на `THIRD_PARTY.md` |
| `run_own.m`, `run_own.py` | Автономная демонстрация MATLAB/Octave и Python через `common/own/`, без сторонних исходников |
| `images/` | Графики для README; сторонние картинки алгоритмов сюда не копируются |
| `python/`, `octave/` | Точки входа переносимого контракта |
| `sv/`, `tb/` | Поведенческая SystemVerilog-модель и её проверочное окружение |
| `tests/` | Проверки модели |

Для README сохраняйте разделы «Что это», «Как работает», «Структура каталога», «Как запустить», «Что смотреть», «Ограничения»; быстрый старт в MATLAB размещайте внутри «Как запустить». `run_own` должен работать и в публичной копии. Проверка полноты точек входа и Python↔Octave находится в `tests/test_own_models.py`.

Эта структура обязательна для новых моделей. У существующих `ofdm_awgn`, `fsk_text`, `qpsk_script_*` автономные точки входа из MATLAB-сборника не добавлены. Генераторы `tools/create_workspaces.py` и `tools/setup_new_models.py` сохраняют вручную поддерживаемые `run_demo.m`, `run_own.*`, `images/` и существующие README; новые точки входа и изображения нужно добавить при создании модели.
