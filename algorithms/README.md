# Модели алгоритмов цифровой обработки сигналов

В этом разделе собраны 11 модулей DSP: адаптивные фильтры, обработка решёток и аудио, канальные банки, LDPC, линейное MIMO-детектирование и синхронизация. Каждый модуль имеет единый числовой контракт для Python, Octave/MATLAB и поведенческого SystemVerilog с UVM; связанные потоковые fixed-point блоки находятся в общем RTL.

## Что это

Модули выделены из исторических MATLAB/Octave-коллекций и учебных материалов в виде ограниченных воспроизводимых операций. Их назначение — проверять алгоритм на заданных входах и сравнивать реализации по всем выходным значениям. Они не воспроизводят автоматически все исторические демонстрации, графики и большие статистические эксперименты.

Текущий [набор сценариев](../tools/research_cases.py) содержит 30 случаев для этих 11 алгоритмических модулей. [Сохранённый снимок от 2026-10-01](../docs/typed_verification_results.json) фиксирует межъязыковые проверки и отдельно выбранные сравнения с оригинальными функциями; результаты относятся к исходникам своего снимка. Общий runner содержит также OFDM и FSK из каталога модемов: без фильтра workspace он выполняет 40 сценариев в 13 группах.

Исторические модели и сторонние материалы в публичный репозиторий не входят. В каждом локальном `model.json` записаны происхождение, размер в байтах и SHA-256 каждого исторического файла, а также операции, сценарии и ограничения переносимой модели. Обычная переносимая регрессия работает без исторических исходников. MATLAB-сравнения оригиналов доступны только при их наличии.

## Как работает

1. Локальный `python/model.py` предоставляет `run(operation, parameters, signal, auxiliary)` и вызывает [research_core.py](../common/python/research_core.py).
2. `octave/run_model.m` и `matlab/run_model.m` вызывают одно [M-ядро](../common/octave/research_core.m). Четвёртый аргумент можно опустить, если операция не использует вспомогательный массив.
3. Локальный `sv/model.sv` подключает поведенческий DUT через `research_if`. Транзакция содержит номер операции, параметры, вход и вспомогательный массив. Ожидаемые результаты получает scoreboard, а не DUT.
4. Сценарии создают фиксированные или воспроизводимые случайные входы и проверяют независимые критерии: аналитические ответы, SciPy-эталоны, сходимость, синдром, правильность решений или уменьшение MSE.
5. Runner сохраняет общий набор векторов и сравнивает с ним M-ядро и SV. UVM повторяет последовательность после сброса и проверяет обнаружение намеренно неверного ожидания.

| Соглашение | Значение |
| --- | --- |
| Источник операций и сценариев | Локальный `model.json` |
| Источник числовых параметров тестов | [tools/research_cases.py](../tools/research_cases.py); универсальной конфигурации `config.json` у этих модулей нет |
| Массивы | Плоские комплексные массивы; матрицы по строкам, индексы с нуля |
| Частоты | Циклы на входной отсчёт, если для конкретной операции не указано иначе |
| Начальные состояния | Задаются заново на каждый вызов согласно контракту операции |
| Случайные сценарии | `numpy.random.default_rng(20260930)` в общем наборе |
| Поведенческий UVM-допуск | `1e-8·(1+abs(expected))` для каждого комплексного значения |

Подробные входы, выходы и единицы приведены в [TYPED_MODELS.md](../docs/TYPED_MODELS.md) и README отдельных модулей. Поведенческий SV использует `real` и обработку целого блока, поэтому межъязыковой PASS не доказывает синтезируемость или fixed-point точность.

Отдельные блоки в [rtl/common](../rtl/common/) имеют целочисленные Python-эталоны и потоковые `s_valid/s_ready/s_last`, `m_valid/m_ready/m_last` с конфигурационными портами там, где они нужны. Передача происходит при `valid && ready`; это плоские интерфейсы. Базовые отсчёты многих блоков — signed18 Q15, спектры STFT/PFB — signed24 Q19, LLR LDPC — signed16 Q8. Нормировки и темпы различаются: аппаратное прямое FFT выдаёт `X/N`, а переносимая DFT — `X`. Форматы, латентности и ограничения описаны в [DSP_RTL.md](../docs/DSP_RTL.md), [FFT_RTL.md](../docs/FFT_RTL.md) и локальных README.

## Как запустить

Все команды выполняются из корня проекта. Python-ядрам нужен NumPy, runner дополнительно использует SciPy. [requirements-visual.txt](../requirements-visual.txt) включает их и Matplotlib для визуализации. Для M-ядра нужен `octave-cli` либо MATLAB без дополнительных toolbox. [MATLAB launcher](../tools/matlab.sh) поддерживает `MATLAB_ROOT`; проверявшийся MATLAB R2020b на этом хосте требует запуск из терминала. Для поведенческой SV-регрессии нужны Questa и UVM 1.2; при нестандартной установке задаются `QUESTA_HOME`, `UVM_HOME`.

Пример запуска одного модуля:

```bash
python3 tools/run_research.py --suite python --workspace filters/windowed_sinc
python3 tools/run_research.py --suite octave --workspace filters/windowed_sinc
python3 tools/run_research.py --suite matlab --workspace filters/windowed_sinc
python3 tools/run_research.py --suite hdl --workspace filters/windowed_sinc
```

Значение `--workspace` берётся из локального `model.json`, без префикса `algorithms/`. Все варианты сначала вычисляют Python-эталон; `octave` и `matlab` сравнивают с ним M-ядро, `hdl` запускает UVM и отрицательный контроль. Локальный `tb/run.sh` вызывает HDL-suite своего модуля. Python должен работать без `-O`, поскольку приёмка использует `assert`.

Полный набор общего runner, включая упомянутые OFDM/FSK:

```bash
python3 tools/run_research.py --suite all
python3 tools/run_research.py --suite matlab
```

`all` объединяет Python, Octave и HDL; MATLAB запускается отдельно. Для потокового fixed-point RTL используйте команды конкретного README: им дополнительно нужны Verilator для lint и [requirements-rtl.txt](../requirements-rtl.txt). Эти DSP-runner не выполняют вендорный синтез.

Только при наличии полного локального набора исторических исходников:

```bash
python3 tools/run_matlab_evidence.py --suite references
python3 tools/check_research_references.py
```

Первая команда получает MATLAB-захваты выбранных оригинальных LMS/NLMS/RLS, PFB/WOLA, LDPC и проверяет timing PI-константы, а также несколько переносимых модемов. Вторая сравнивает захваты адаптивных фильтров, канальных банков и полноразмерного LDPC с Python. В публичной поставке без исторических материалов этот маршрут недоступен; он не нужен для обычной переносимой регрессии.

В каждом алгоритмическом модуле есть также [run_demo.m](adaptive/lms_nlms_rls/run_demo.m): перейдите в папку модуля и выполните `run_demo` в MATLAB/Octave. Обёртка запускает выбранные исторические скрипты и графики из локального `original/`; они не входят в публичный репозиторий, см. [THIRD_PARTY.md](../THIRD_PARTY.md). Конкретные зависимости и длительность указаны в README модуля. Переносимые `run_research.py`, `python/model.py`, `octave/run_model.m` доступны и в публичной копии.

## Что смотреть

Готовый [визуальный атлас](../docs/typed_visual/index.html) содержит графики по workspace; каждый локальный README сохраняет ссылку на свой раздел и изображение проверочного случая. [Описание контрактов и проверки](../docs/TYPED_MODELS.md) и [исторический снимок результатов](../docs/typed_verification_results.json) объясняют область подтверждённого поведения.

| Результат запуска | Содержимое |
| --- | --- |
| `build/typed/<category>__<name>/` | Результаты запуска одного алгоритмического workspace |
| `build/typed/` | Результаты запуска без фильтра workspace |
| `cases.json` | Имена сценариев, размеры, метрики и контрольные суммы захватов |
| `case_*.npz` | `parameters`, `x`, `a`, `y`, при наличии — чистый сигнал `truth` |
| `vectors.txt` | Общий текстовый контракт векторов для M- и SV-проверок |
| `<suite>_results.json` | Статус, время, контрольные суммы исходников и артефактов |
| `octave_cases.json`, `matlab_cases.json` | Максимальная числовая ошибка каждого случая |
| `questa/` | Компиляция, основной UVM-запуск и отрицательный контроль |
| `build/rtl/<suite>/` | Отдельные fixed-point векторы, результаты и RTL-журналы |

Успешный runner возвращает код 0 и пишет `status: PASS` после завершения проверок. В основном UVM-запуске нужны нулевые `UVM_ERROR` и `UVM_FATAL`; отдельный `negative_control.log` должен показать обнаружение намеренной числовой ошибки. Статус `RUNNING`, неполный отчёт или оставшийся от другого снимка PASS не подтверждают текущую версию.

Метрики выбираются по задаче: MSE и её уменьшение для адаптации/шумоподавления, остаточная помеха и утечка для фильтров/решёток, ошибка реконструкции для STFT, ошибки бит и синдром для LDPC, правильность решений для MIMO. Нулевой синдром LDPC отдельно дополняется сравнением с переданным словом. Одиночные сценарии с нулём ошибок не являются статистическими BER/SER-кривыми; RMS/SQNR fixed-point тракта измеряются отдельно.

## Ограничения

Переносимые операции имеют меньший объём, чем исторические коллекции. Здесь не воспроизведены все OSET/Mathcad/книжные примеры, исторический IMCRA tracker, полный набор timing TED/интерполяторов, MMSE-SIC и длительные Monte Carlo BER/FER-прогоны. Подробности и доступные исходные проверки перечислены в README каждого модуля.

Согласование Python, M и `real`-SV проверяет общий алгоритмический контракт. Потоковый RTL имеет собственные форматы, насыщения, ограничения размера, нормировки и последовательные участки. Его битоточность устанавливается относительно целочисленного эталона; совпадение с floating reference и физическая частота требуют отдельных измерений. Для многих DSP-блоков вендорный синтез отложен; исторические физические результаты FFT/STFT не распространяются автоматически на последующие изменения.
